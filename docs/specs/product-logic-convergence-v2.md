## 2. 核心业务合同

`C_v` 是客户当前明确应用的 CustomerUpload 与有效 LedgerRevision/Profile；`A_v` 是明确来源、域、空间与范围中已发布且可读的云图版本。IP/port 域分别固定，不伪造全域同一快照；其他 16 类独立阅读保持原合同。`S` 包含 tenant/project、确认 namespace 与本次可比范围。`R_k` 固定 C_v、A_v、S、规则/合同版本及生成时间。`E_j` 只保存明确 R_k 与 N_w 的辅助绑定及所需审计身份。

在可比 S 中，以现有规范 IP 为粒度：

- 全部地址 = C∪A；双方都有记录 = C∩A；云图有记录、客户本版未登记 = A−C；客户有记录、云图本批未观测 = C−A。
- N 不参与上述全集、分类、筛选总数。N−(C∪A) 单独列为补充线索，不自动成为自有资产、漏管、违规、Resource 或 Finding。
- IPv4、IPv6、mapped 地址规范化及原记录身份沿用现有实现。同 IP 多原始行、服务/域名继续可分页追溯；IP 命中不是实体合并或归属证明。
- 未确认同空间不得按 IP 字面值跨源合并。确认固定于确切输入与范围；当前撤销阻止新生成，新版不自动继承旧确认。没有唯一上下文时只要求业务化范围选择/必要 Admin 确认，不猜 NAT、SRC/DST 角色或所有权。
- C/A 缺失、读取失败、范围不明时不能生成完整三类结论；范围内合法空集按各自原输入合同判断。客户非法空文件仍拒绝，不能为了空集测试放松校验。部分覆盖可呈现已读事实与限制，共同/差异统计不得冒称全范围核对。
- “双方都有记录”不等于完全一致或无风险；“客户本版未登记”须待核实；“云图本批未观测”不等于下线。源侧观测端口、云图端口与客户声明端口分别解释；缺失的协议、时间、流量大小等不伪造。

## 3. 默认解析、发布与固定阅读

普通 `/projects/{project_id}/netflow-correlation` 称“比对结果”，由服务端在明确作用域内解析最新常规、已成功发布、当前可读的 V2 核心结果。候选查询覆盖完整集合，按发布次序及稳定身份排序并逐项执行必要授权/保留/完整性检查；不从前端第一页 `data[0]`、最近上传或浏览器上次选择推断。

常规发布和自定义旧输入核查明确区分用途。旧 V1、自定义历史核查不因创建时间较新而抢占普通入口；失败/运行中/未知更新也不覆盖旧成功结果。只有已知权限/期限不可读候选可以按原目录合同排除，完整性损坏与未知读取错误不能变成空结果或悄悄跳过。

V2 至少持久化可判定的 `purpose=regular|custom`、发布状态、`published_at`、固定结果ID和作用域身份；不把旧 `scope_state` 或创建时间独自当作已发布。只有 regular、成功发布、scope CONFIRMED、C/A 当前可读的候选可进入默认解析，按 `published_at DESC,id DESC` 确定排序。若本地确定性生成与发布同一事务，成功提交时固定发布时间；未成功事务不得留下伪已发布结果。更新尝试的失败/进行中/未知状态与成功结果分开保存/返回；不存在后台任务时不得伪造 RUNNING 记录。常规当前发布检查预期作用域修订，迟到请求冲突不能以较晚时间成为新的当前结果。

解析后将结果身份固定到 URL/页面。后续筛选、分页、详情、刷新、返回只读取同一版本。浏览中发现新结果只提示；历史显式 ID 不可读时拒读，不重新解析 latest。账号/项目/来源切换、撤权、到期清除对应缓存、详情和未提交意图，晚到响应不能复活旧内容。

首屏依次显示生成时间、所用客户版本/生效时间、云图具体版本/采集时间/范围、核心总数与三类统计、差异列表。主操作“更新比对”；次级“历史结果”“查看本次资料”。默认不展示 Dataset/Context/Analysis/Revision 选择器。列表为 IP、两侧记录、核对结论、可选流量依据与查看依据；详情保留完整技术身份、原材料与实际可执行下一步。

无结果但 C/A 就绪时显示“生成比对结果”；否则精确提示缺失的客户/云图资料或范围确认，NetFlow 不是前置。元数据读取失败显示错误，不能显示尚无结果。

三类动作分开：刷新仅 GET；更新比对仅使用已落地的当前应用 C 与指定范围内的已发布 A；同步云图、上传/处理 NetFlow 是各自明确的写操作。更新比对不隐式调用来源、processor 或模型。

生成就绪与更新状态由服务端统一计算。当前 C/A 改变仅提示可重新比对，原 R_k 的统计/引用不变；状态读取失败显示“暂无法确认是否有更新”。更新请求固定输入、范围确认和预期当前发布修订，在 Project/作用域串行边界内检查；同 actor/project/操作/key 同请求恢复同一结果，异请求冲突，未知回执用原 key 读回。过时输入或迟完成的并发操作不能逆向替换当前发布；失败/冲突保留旧成功并给出真实状态，不用异步新调度器解决本地确定性计算。

## 4. NetFlow 当前列表与辅证

复用 Analysis/observations/peers/evidence API。普通 `/projects/{project_id}/netflow-results` 在项目已确定的来源/采集范围与 namespace 内跨 Dataset 解析最新成功、封存、可读 Analysis，再固定 ID。多个互不兼容范围不得自动合并或按最后上传文件选全项目数据；无法唯一解析时提供来源/范围选择。成功警告保留警告；合法成功空集优先于更旧的非空；失败、未处理、全部隔离、无权限、到期不能显示为 0。

采集范围须有持久、可核验的来源/范围标识与确认依据。优先复用已有可信字段；不足时仅补 Context 的最小显式采集范围声明/确认，不新建范围治理平台。跨 Dataset 只有明确确认属于同一范围的成员才可竞争最新；仅同 namespace、相似字段、current Dataset、最近上传或时间相近都不构成证明。旧材料无此凭据时不自动回填或合并，独立作为可业务化选择的范围；一个唯一合法范围可直接解析，有显式项目上下文则先核验并尊重它。

最新处理尝试状态与最近成功数据分别展示。处理完成时间与实际观测窗口分别标注；旧窗口晚上传/重处理不能称为最新网络活动。保留协议、源侧观测端口、IP、排序、分页、详情和证据；源侧与外侧对端分视图，条目数/对象数/不同 IP 数分开，缺失字段标未提供。

实际窗口只取成功封存的受控结果或已验证上下文中的真实字段；当前没有此字段时返回 UNKNOWN/NOT_PROVIDED及原因，不能拿 created_at/completed_at、上传时间或不完整样本极值替代完整观测窗口。E_j 固定该真实值或UNKNOWN及其出处，不要求伪造窗口来满足绑定。

E_j 固定核心 R_k、Analysis、Dataset/Context/namespace/所用反馈版本（若消费）、绑定时间、实际窗口及资格依据；追加变化不回写旧绑定。辅证页面查询仍通过原受控 reader 验证当前权限、期限和内容完整性。未提供、没有匹配、窗口不可比、失败/撤权/到期分别表达，均不修改核心分类。

辅证失效清除其行、计数、结论、详情和导出内容，只保留授权可见的非敏感状态；仍可读的 C/A 核心继续显示。不可把 NetFlow 敏感内容或自由文本复制进核心摘要延长寿命。核心成功发布与可选辅证尝试分开提交/报告，N 失败不能撤销已发布核心。旧 V1 仍在任一所选依赖不可读时整份拒读，不能删 N pin、吞 403/410 或回读原始活动账。

沿用每对象实际期限；旧 Analysis 无期限时显示历史规则，不虚构已实施 TTL。本轮不实施 #287、不续期、不自动回填/迁移/清理历史。将旧 V1 转为 V2 必须显式用当下合法可读 C/A 创建新身份，旧记录不变。

基线 Analysis 没有结果TTL，本轮不得称其为“Analysis已到期”。为实际实现新辅证的独立期限，新增 E_j 自身的显式 `valid_until`：附加时由操作者明确给出未来截止并固定，不提供隐含90天默认；存在已实现、可验证的上游截止时，绑定不可超过该截止。到期只拒绝该 E_j 的辅证正文/派生统计，清除页面对应缓存，核心不受影响；底层 Analysis 是否仍可独立阅读继续按它真实的原合同。此项不修改 Analysis 或原始 Dataset 的存储期限，不提供物理清理。验收明确区分“绑定到期”和“Analysis到期”，后者在#287未实现时不能冒称通过。

## 5. 接入、客户版本与返回

主导航顺序：比对结果、云图资产、客户资产台账、NetFlow 观测。项目设置统一“数据接入”；历史与治理仍为次级，旧 Run/报告深链不改义。三个数据页默认当前可读版本，历史与更新为明确操作。

数据接入按客户/云图/NetFlow 分组，分别展示配置连接状态、上传接受状态、导入/同步/处理尝试状态、实际可读发布版本。不能以 enabled/validated 连接或原始 Dataset 存在冒充可用比对输入。来源数据页与中央接入复用同一受控表单/服务，保留权限、失败恢复、预算与范围说明。

ProjectPreparation 普通“确认输入并开始”进入新核心生成/结果路径，不能进入旧 `view=runs`。显式历史 `view=runs` 保留 GovernanceRuns 的原义；根页面、Logo、Sidebar、WorkspaceSelector 同时核对普通入口和显式历史参数，保留 #290 固定 query 修复。

客户替换仅由 #285 落地：严格接受不改变当前；服务端全量预览条目数/不同 IP 数、新增/移出 IP/同 IP 声明变化；同 IP 多行不合并；显式应用检查预期 upload/revision/profile，以幂等事务切换当前和审计。失败、冲突、丢回执不丢旧版，历史只读不改变当前，不变成增量并集。单条人工更正沿 ADR-0018 原事务；不扩建客户系统。

结果的“查看依据”打开本次固定来源版本；“查看当前版本”是另一个显式动作。返回保留结果 ID、筛选、页码和必要选择，仅允许同项目受验证的内部上下文，不接受任意外部 return URL。旧 query/hash 深链只作等义承接，不丢固定身份。

## 6. API 与持久化实施边界

以下是待批准的能力差额，不宣称当前 API 已存在；精确路由/DTO 按现有服务最小扩展并由代码生成客户端：

| 能力 | 复用与最小扩展 |
|---|---|
| 当前核心结果、就绪和资料更新摘要 GET | SourceCorrelation 可读目录与固定 reader；增加 V2/常规用途、明确范围及最新成功解析；错误不伪空 |
| 常规核心生成及原 key 恢复 | 复用 `netflow=null` 的创建/固定/幂等；增加必要用途、预期输入/发布修订及并发检查；不改 V1 创建含义 |
| 核心摘要/地址/依据 GET | 复用同一两源全集；三类统计、准确筛选 count 和稳定分页；旧 V1 查询结果不改义 |
| 独立辅助绑定与读取 | 仅持久固定身份/审计，不复制明细；同范围权限和独立失败状态；明确版本读取 |
| 当前 NetFlow GET | 复用 Analysis 发布/可读验证，跨 Dataset 按明确采集范围解析；区分最近成功和最新尝试 |
| 客户全量 preview/apply/recover | 唯一任务 #285；复用接受、规范行读取、Project 锁、CAS、请求哈希与审计事务；不能把旧无 CAS 的 select 当新 apply |

PostgreSQL 为唯一结构化事实库；复用 Python/SQL/Polars、agent-compose 生命周期与 OctoBus 边界。必要 Schema 仅追加迁移，新增索引/约束保护用途、幂等与发布身份；不重写共享迁移。迁移必须保留旧行/Hash/引用，无法无损降级时拒绝，不为回滚删用户数据。前端 client 运行 `bash scripts/generate-client.sh`，routeTree 由现有 Vite/TanStack 插件生成；两类生成文件不手改。不引入新计算平台、调度器、规则 DSL、默认多 Agent、自动纳管/处置/扫描/外部写回或新 AI 链。

## 已批准要求

### 工作流

治理人员以 IP、发现类型和业务状态识别问题。看到各来源观测、数据时间和活动线索后，对明确的单个资产或发现手动发起 AI 核查；可在同一 Project/资产/已发布基础 Run 范围内追问。保存人工结论；该结论尚不代表 Finding 已解决。后续成功且兼容的对账验证原差异已解决、仍存在或证据不足。可手动生成一次对账的分析报告；无核查时如实说明缺口。Viewer 只读，不能触发模型、写入人工结论或确认报告。

### 权威事实与时间

PostgreSQL 与确定性处理仍是结构化业务事实来源。AI 或人工说明不更新 GovernanceRun、SourceSnapshot、IPSourceComparisonFact、Finding 或已有 GovernanceReport 的权威内容。核查固定 Project、Resource、基础已发布 Run，以及相关 Finding（若从发现项发起）。追问延续该范围，不静默切到 latest。新的只读查询记录查询时间与引用身份，不得覆盖原 Run 快照或混入原 Run 统计。未执行、未成功或越权的查询不能产生肯定性新事实。失败记录可引用为局限，不能当作成功 Evidence。

### AI 核查

Pi 执行受限模型会话，模型只调用白名单工具；至少包含明确范围内的系统事实/历史读取和既有 CloudAtlas 的 OctoBus 只读能力。每个工具参数和返回值由服务端复核授权与范围。模型不得获得数据库凭据、应用 Secret、任意 Shell/SQL/URL、Artifact 原始文件或外部写能力。核查和每轮追问有可观察状态与部署固定的工具/数据量/时长上限。未知 Session 不得解释为成功或自动另开重复执行。请求重放保持幂等；失败后的再次人工尝试保留原失败记录。不得以自动换模型/Provider 或无界 retry 强行完成。输出分清事实、解释、缺口和建议。引用检查验证身份和范围；有引用不等于语义正确。

新核查及追问的事实文字、解释、缺口与建议使用简体中文、结论先行和简短业务语言；以真实 IP、来源及必要的观测/查询时间说明范围。不在自由正文中罗列 UUID、Hash、引用 ID、合同版本、原始字段名或状态/错误码；完整身份与引用不删改，保留在结构化字段和固定材料中。必要错误、资料缺口与 NetFlow 活动局限仍须明确说明，不因简短而省略。此约束不回写历史正文、不改变事实或自动保证模型语义正确，须以真实新生成结果验收。

### 人工记录与后续验证

人工记录保留作者、时间、关联对象、基础 Run、结论及待验证事项；更正追加版本并保留原记录。验证只回答原一致性差异是否被后续事实解决。关联同一 Project/Resource 的后续成功且兼容 Run：满足既有确定性关闭规则才显示已验证解决；仍存在差异显示未解决；不足以判断则显示证据不足/待验证。NetFlow 的 ACTIVE、零记录或缺失均不单独关闭 Finding。已发布的后续 Run 与验证结果不可重写；再出现失败 Run 时保留原成功验证身份。

### 分析报告

用户手动生成/更新草稿，以一个明确 Run 的完整确定性摘要为主体，可读取有界历史与已保存核查/人工记录。模型不自行汇总权威总数，不编造业务归属、严重性、因果或已完成动作。保存 AI 原稿与人工编辑；人工确认是独立动作。统计、身份和引用不可当作随意修改字段。新材料出现时，标题/主要操作区醒目标明未纳入此版本，并提供生成新草稿入口；完整旧版本保持可读。新草稿不自动确认，也不自动覆盖已有草稿/确认版历史。

可读性修订（#220）：正文简体中文、结论先行、短段落与业务语言；固定材料和引用中保留完整追溯身份；统计只复述权威事实；区分当前差异、历史积压及无数据/零风险。

历史归属修订（#221）：正文按资产、按 Run 说明不同轨迹。不得把某一个资产的生命周期套用于整组资产。结构化引用合法不能代替这项语义。截断历史须标明缺口。

### 页面与权限

默认阅读顺序：资产情况 → 核查进展/验证 → 分析报告。“查看依据”保留技术追溯。列表主标识为 IP、发现类型等业务信息；完整 ID/Hash 可复制，短显示不改变引用身份。窄屏与键盘可用。Operator 执行核查、记录和报告编辑/确认；Viewer 只读；Admin 保持既有显式权限。每个服务端操作复核项目授权。保留简体中文/英文、明确的空/加载/失败状态，以及确定性报告的独立可用性。

### S1 概览入口与业务阅读

#### 行为

1. **核查入口。**概览提供“台账未登记，外部已观测且有活动”（`classification=cloudatlas_only`、`netflow_status=ACTIVE`）和“台账已登记，外部未观测但有活动”（`classification=customer_upload_only`、`netflow_status=ACTIVE`）两个快捷入口，复用已有三源比较及筛选，从第一页开始并清除遗留资产选择。它们仅表示核查线索，不构成评分、严重性、已确认风险或完整风险清单；保留“查看全部资产与差异”。
2. **计数边界。**数字必须来自明确 Project、Run 和完整筛选范围的权威结果。不得使用当前页行数、截断血缘节点或两个独立维度总数推导交叉数量。S1 概览快捷入口不显示数量，也不新增交叉计数请求；已有完整批次摘要及比较页服务端筛选总数保持各自范围说明。缺失、UNKNOWN、无匹配和请求失败不能混同为零。
3. **范围连续。**路径为概览 → 带条件三源比较 → “查看资产并核查” → 已有 `/projects/{projectId}/runs/{runId}/lineage?resource_id={resourceId}` 单资产范围。该页业务事实优先，复用已有 AI 核查与人工记录面板；原有血缘、节点和路径按需展开，不新增页面或图组件。从概览到核查保持同一 Project、Resource、已发布基础 Run，返回比较保留筛选和页码。未选择批次时可沿用已有解析并固定到 URL 的行为；显式历史批次不可被 latest 替代，也不能用 latest 资产弹窗的事实承接历史阅读。范围不匹配、不可用或读取失败时，不展示其他批次事实，不允许基于错误范围发起核查。资产入口不擅自绑定 Finding；明确发现项入口沿用其 Finding 身份。
4. **业务标识。**默认以 IP、可信且已存在且属于该范围的资产名称、差异类型、来源和时间组织阅读。名称缺失时只用 IP，不伪造名称、不引入新数据源或跨批次拼接。批次以时间为主标识；显示标签不作为身份 key。来源时间、活动证据局限、读取失败及资料缺口留在业务阅读区。
5. **技术追溯。**演示涉及的概览、比较、单资产核查、批次选择、客户上传/配置、运行记录、AI 核查及分析报告默认收起 UUID、Hash、Profile ID 及完整引用身份。详情可展开、完整读取、复制且键盘可操作；折叠标题本身不暴露长技术串。底层字段、选择值、请求参数、引用和校验不变。复用已有完整值复制和原生折叠能力，不建立新的通用身份框架。人工记录及确定性报告已有折叠结构继续复用；分析报告保留 B0 已修正的确认正文与 AI 原稿分离。
6. **既有业务边界。**进入页面不触发模型；权限、人工记录不直接关闭 Finding、后续验证不改写基础批次等既有约束不变。Viewer 只读。AI 自由文本中的英文或技术串不通过正则删改；收起结构化元数据不代表解决自由文本可读性。仅按本次明确批准的核查可读性补充调整新生成指令，保留历史原文；若新结果仍干扰演示，单列未通过项，不冒充解决、不自动扩为其他模型改造。

#### 验收

- **AC1 — 两个入口可用：**使用 B0 首轮成功批次，两个入口分别能找到 `192.0.2.46`、`192.0.2.20`，并进入对应资产、同一基础批次的核查区域。页面打开不触发模型。
- **AC2 — 历史范围不漂移：**后续补齐台账的成功批次已存在时，从首轮进入仍显示首轮差异；刷新、前进后退、分页和核查请求保持身份。显式切换批次后才读取新批次。跨项目、跨资源或批次不可用时 fail closed。
- **AC3 — 没有伪总量：**快捷入口无数量；比较结果超过一页时，总数来自服务端完整筛选结果，不随分页变化。无匹配、缺失、UNKNOWN、请求失败分别呈现，不统一显示为零。
- **AC4 — 默认阅读无结构化技术身份干扰：**上述演示页面默认以业务标识阅读；展开后能读取并复制完整 UUID、Hash、Profile ID 和引用身份，复制结果与原值一致。来源、时间、状态与必要错误说明不被隐藏。
- **AC5 — 可访问性与回退：**桌面及 390px 窄屏可完成入口、筛选、核查阅读和详情操作；键盘可展开、复制、返回，关键操作不被溢出隐藏；保留中英文及加载/失败状态。
- **AC6 — 业务与身份不变：**Viewer 不获得写权限；页面打开不产生模型任务；既有引用校验继续有效；历史核查、人工记录、确认报告及确定性事实不因展示调整被修改。

S1 以一张任务交付入口连接、演示阅读分层及保护检查。不扩大为整站重构；不新增评分、大屏、图组件、AI 底座、同步接口、导出模块、资产名称数据源或 S2/S3 能力。开发验证与下一会话独立业务验收分别记录；源码、mock 组件检查或 CI 通过不等于 B0 实际材料的 S1 业务验收通过。

### EXP-UX-01 新建项目、准备输入与首轮比对

维护者于2026-09-12在当前会话批准本切片及其定稿：完整“创建→准备→首轮比对”，包含视觉与失败恢复，不包含LLM配置。本节是该授权的本地规格定稿；尚未提交、推送或绑定正式Issue，不能预写不存在的commit。它新增创建/准备入口及恢复合同，继承S1的固定批次、技术身份折叠与全部业务保护；不改变旧结果或历史验收，不批准EXP-UX-02–04。

#### 创建与权限

- 全局superuser可以从零项目首页和项目选择器创建；只要求项目名称，去首尾空白后1–255字符。服务端固定部署tenant，拒绝客户端tenant或额外字段。Operator/Viewer不获得创建权；已有项目操作继续按项目授权复核。
- 创建在同一数据库事务中产生Project、默认CustomerUpload Profile与一次创建审计。新UI在首次网络请求前生成并保存稳定Idempotency-Key；服务端按tenant、actor、创建操作与key绑定规范化请求及结果。相同key和请求返回同一Project；相同key不同请求409；并发与响应丢失不得重复创建Profile/审计。不同key允许同名项目，旧无keyAPI保持兼容。
- 成功后进入新项目的准备页，清除旧Project/Run/Resource/筛选与分页上下文。未知结果不显示成功、不自动换key；项目已经归档或访问被撤销时，不以重放恢复可写权限。

#### 准备与确认

- 准备页首屏展示三来源状态和下一步，复用现有管理控件/页面。台账仅接受现有XLSX合同，外部观测仅通过SourceInstance绑定、验证、启用与OctoBus读取；NetFlow接受现有CSV/TXT合同，可显式不选择。不新增三份任意表格上传、CloudAtlas文件导入、XLSX兼容放宽或生产连接承诺。
- 台账/NetFlow明确区分已接受、当前选中、本轮已固定。CloudAtlas显示绑定/验证/启用与部署依赖；其状态不等于当前连通性已复验。单项失败保留其他已接受输入。未选择NetFlow为v1两来源；选中后为v2，合法零记录/无正向活动不等于无活动或零风险。
- 启动前显示当前选中台账版本、CloudAtlas来源/验证身份及NetFlow版本或明确absent。服务端提供与这些展示字段对应的确认身份，优先复用现有PinnedTriggerInputs的规范化input_hash；未就绪不提供可提交的确认身份。读取准备状态不启动任务、不探测模型，不把列表ready当最终保证。
- 新UI启动请求携带确认input_hash与稳定Idempotency-Key。服务端在项目锁保护下、首次持久化launch reservation之前重新检查授权、归档、来源就绪/实时指纹与当前选中输入，并比较确认hash；变化以409及稳定脱敏码拒绝，要求重新读取、人工确认。不得先启动后检查，也不得将当前输入静默替换为用户未确认的版本。NetFlow的present/absent、台账Profile版本与现有合同身份均参与比较。
- 同key重放已建立Run或launch reservation时对照原已固定输入身份；不能用现在的输入重写旧请求。异确认身份冲突，原请求状态不变。既有无确认字段调用保持原有兼容语义，但新UI始终携带确认身份；不削弱已有服务端就绪、固定输入与并发保护。
- 确认的是输入版本与来源连接身份；CloudAtlas运行时读取形成快照，不能承诺上游资产内容在确认至读取之间不变化。快照、来源时间和Run身份继续由既有runner固定和校验。

#### 超时、刷新与账号隔离

- 浏览器恢复记录按已认证用户、操作和Project隔离；创建尚无Project时按用户隔离。只保存恢复所需的key、规范化项目名称或确认hash、返回的Project/Run/控制运行身份；不保存凭据、上传字节或资产原始数据。使用同标签页可跨刷新的存储，存储不可写或记录无效时在发送前明确阻止该动作，不能退化为不可恢复的提交。
- 请求前持久保存；收到201/200确定项目身份后可转入准备页并清理创建意图。Run的202且业务Run尚未建立是“已受理，待建立批次”，继续保留key和控制身份；502/503、网络中断或未知Session不自动清key、换key或新建执行。只按原key恢复，轮询真实状态；页面打开/刷新只读取，不自动POST。
- 人工“恢复查询/确认原请求”可复用原key重放入口，语义必须明确：若原请求从未到达，此操作可能首次提交同一已确认意图。状态未知期间不能把该动作写成纯查询，也不能自动再次执行。已有Run时固定其ID，不能通过“列表多了一条”猜测本次Run。
- 服务端明确拒绝且未建立预留时可重新确认并开始新意图；控制运行已证实终止且无业务Run时按既有终态恢复合同允许人工新意图。业务Run失败保留原记录，复用现有Retry/Rerun边界，不新增自动重试、不冒充完成。
- 登出/认证失效或账号切换立即撤下旧账号的恢复UI、取消其未完成页面查询并隔离/清除相关查询缓存；未认证或另一账号不得读取、显示或重放该意图。未决非秘密恢复记录可以保留至同账号重新认证后继续，避免登出直接丢掉未决key。已完成且已确认结果后清理；关闭标签页后的跨设备恢复不是本片承诺。即使本地记录丢失，服务端幂等、项目单活跃Run及launch reservation保护仍有效，不自动启动。
- 切换Project/Run或账号后，晚到响应不能导航或填入新上下文。权限撤销时禁止写入/恢复动作；历史结果只能依现有授权读取。

- AC01-1：零项目与选择器入口可发现；名称/权限/tenant正确；创建并发、丢响应、刷新、异payload冲突及默认Profile/审计一次均通过。

- AC01-4：覆盖请求未到达、服务端成功但响应丢失、202尚无Run、控制面不可用/未知、刷新、切Project与账号、晚到响应；不会重复建项目/控制运行/业务Run，不错认其他运行，存储失败在发送前可见。

### EXP-UX-02 产品模型连接的安全版本与实际启用

维护者在 EXP-UX-01 交付后批准按本轮规划继续本切片：先固定本节与配套 [ADR-0017](../adr/0017-product-model-connection-lifecycle.md)，建立正式 Issue，再以隔离的版本绑定试验验证运行时方案，随后接入产品设置。此节新增单部署模型连接生命周期；EXP-UX-01、原业务材料、引用、权限及历史事实合同保持。正式任务必须引用本节首次发布后的真实 commit，规划 Seed 不替代 Issue。

#### 范围、角色与版本

- 独立“AI 设置 / 模型连接”入口与账号资料、密码及 CloudAtlas 数据源分开。首版仅一个部署级生效连接、至多一个待启用版本，保留被替代/禁用的历史版本；不做多模型路由、项目级覆盖、模型市场或 OMP 配置管理。
- 只有当前全局 superuser 可以读取完整非秘密连接配置、保存、验证、启用、撤销/禁用；每个服务端写操作重新鉴权。普通已认证用户只读必要的可用性与脱敏模型身份，不获得端点、凭据引用或其他项目材料；发起业务任务仍复核既有 Project 角色和数据许可。
- 连接版本包含显示名称、协议、端点、模型标识、凭据版本及已有执行合同所需的非秘密身份。协议和端点语义按现有适配器支持范围校验，界面明确地址格式；不接受任意 provider 参数、命令、模板或任意高级配置。预算与材料许可保持部署控制，不以设置页开放测试绕过开关。
- 已保存版本不可原地改写；修改连接、模型或轮换 Key 创建新版本并重新验证。替换待启用版本保留旧版本和关联验证/任务记录，不能覆写正在验证或启用的对象。历史任务保存实际使用的非秘密版本身份；不把旧记录回填为当前版本。
生命周期判定如下；验证结果独立绑定版本，表中状态不要求实现为一套额外调度器。

| 当前状态/动作 | 允许结果 |
| --- | --- |
| 待启用，未开始验证/启用 | 可显式放弃后保存新版本，保留原历史；不原地改写 |
| 验证中或启用中，包括控制结果未知 | 拒绝替换和重复建立同一动作；原操作查询/同 key 恢复除外 |
| 验证完成但未通过 | 保持非生效，可人工再次验证或放弃；不移动原生效指针 |
| 验证通过并具备当前绑定证据 | 可进入启用；启用失败或未知仍不切指针 |
| B 启用成功，A 原来生效 | B 接收新任务；A 为历史可执行版本，只服务已绑定 A 的任务 |
| 显式撤销 A；或禁用当前生效版本 | A 后续调用被拒绝；若撤销的是当前版本，则无生效连接，不自动选历史版本 |

- 保存、验证、启用是三个明确动作。页面加载/刷新/导航只读，不提交配置、不测试端点、不触发模型。版本没有通过验证或没有完成执行绑定，不能显示“已生效”。同一部署的并发保存/启用通过服务端锁与预期版本检查串行裁决，陈旧请求以稳定冲突码拒绝，不采用最后写入覆盖。

#### 凭据与初始接管

- Key 仅作为管理员写入字段经服务端处理，读取接口只返回“已配置/未配置”和不可反推的凭据版本身份，不返回原文、可恢复片段或明文摘要。浏览器不在 URL、localStorage、sessionStorage、日志、错误或分析埋点中保存 Key；提交结束、离页、登出/认证失效后清除输入。后台也不把 Key 放进 Prompt、审计、普通 API、agent-compose 可读任务参数/输出或原始错误。
- PostgreSQL 保存连接版本、验证事实、生效指针、操作与任务绑定的权威记录。凭据在服务端专用 Secret 记录中以认证加密密文保存，业务版本仅保存不透明引用；使用成熟加密库与独立部署主密钥，不自写密码算法、不引入新的 Secret 服务或第二业务事实库。原生 agent-compose Secret 注入仅是任务传递机制，不能当作已经证实的持久 Secret 管理器。主密钥不得与密文、数据库备份或仓库同存；备份恢复包含 Secret 可解析性检查，缺失时拒绝调用而非取其他版本。
- 仅受信 Supervisor/受限代理可以按已固定任务版本解析凭据；模型子进程不获得数据库、应用、OctoBus、Artifact 或其他连接的凭据。Secret 缓存不得越过撤销检查，日志/失败码须脱敏。Secret 写入成功而数据库事务失败时不得产生可用连接；清理只能针对本次未引用对象，不能删除其他版本或运行中任务依赖。
- 现有环境变量连接在未完成接管前保持原语义，不能因打开设置页自动导入、改变或失效。管理员显式接管时建立有身份的初始版本并核对现有绑定；原始 Key 不送回浏览器。接管清单覆盖 AI 核查及追问、分析报告、旧 AI draft、资格运行/结果及对应 agent-compose Session；仅仍可能发生模型/工具调用或未证实 Session 终态的对象参与运行兼容判断，历史只读不因缺少新版本字段被阻断。无法识别的旧运行绑定以 `legacy_binding_unknown` 阻断首次启用，不能默认已结束；旧 draft 的占位 Session 不能被描述为已执行模型。接管失败保留原可用路径；接管完成后产品任务使用版本化绑定，不再静默读取改变后的全局环境。旧记录仍以原身份读取，不伪造其版本字段。

#### 验证、网络与材料许可

- 管理员显式发起对固定待启用版本的验证，使用固定非客户合成样例；复用现有 Pi、模型资格、受限代理与结构化输出/引用检查。分别显示连接认证、相应核查/报告能力、运行时绑定检查的结果与时间；缺少某层证据即保持未验证，不以 API 200 或配置读回代替。验证不自动启用，也不修改生效连接。
- 保留 ADR-0006/0007 的 http/https、端点格式、全部 DNS 地址校验、固定解析地址、Host/TLS SNI、禁重定向、拒绝 link-local/metadata 与不允许目标等规则；验证与实际模型请求使用同一策略，端点/DNS/协议/模型/凭据版本/Runner 或 runtime 身份改变后旧验证不再满足新绑定。不静默换模型、Provider 或自动 retry。
- ADR-0014/0015 的精确合成例外仍是默认关闭的部署授权，不成为用户可选择的任意公网 Provider。保存 Key 或通过合成资格不授予项目数据出域许可；每次业务模型请求及工具读取继续校验原 Project/Run/Resource、材料白名单和预算。设置页不能修改白名单或借验证发送实际资产。
- 资格验证和任务绑定指纹必须包含连接版本 ID 与不可变 Secret 版本身份，不含原 Key 或对外公开的 Key 摘要，不能只依赖手填的 config_revision。每次解析凭据都复核版本归属、认证解密与固定指纹；同一版本的引用/密文身份被替换、缺失或错配时拒绝使用，不能复用原 PASS。轮换产生新 Secret/连接版本，使新版本重新验证；不因 B 的创建或启用而使未撤销 A 的合法绑定失效。
- 验证记录固定连接版本、合成样例/合同、非秘密绑定指纹、执行身份、结果与稳定脱敏原因。只保存完成判定所需的有界证据，不保存原始 Provider 事件或包含秘密的探测响应。失败后人工再试是新执行，旧失败不改为 PASS。

#### 启用、任务固定与撤销

- 启用要求当前管理员权限、预期生效/待启用版本一致、Secret 可解析、网络/资格/执行绑定有效。先准备并核对该版本的执行路径，再原子切换生效指针；仅数据库写入或执行器配置返回成功不算启用。准备失败、执行回执不符或结果未知时保留旧指针，显示真实失败/未知，禁止假成功和自动重载共享现场。
- 发起业务任务时，在既有幂等与授权边界内固定连接版本及对应模型、资格与执行身份；受信执行器在任何模型请求前按该固定版本重新校验，不从“当前生效连接”替换原任务。既有核查、追问、分析报告和仍允许的资格/历史恢复调用方都须检查，不能只更新设置页。
- 新版本启用后，新任务使用新版本；旧版本变为历史可执行版本而非自动撤销，已建立的任务及其同 key 恢复保留原版本并继续受撤销检查。新的人工追问/新草稿属于新任务，选择发起时的生效版本，并明确显示与历史结果的身份差异；同一个已建立任务内部的后续 turn 不换版本。历史结果和确定性事实不改写。
- 禁用/撤销是独立的管理员动作，立即阻断该版本的新任务和下一次模型请求/受控工具读取；已经发出的网络请求无法承诺收回，但不得继续发起后续调用。被撤销版本不会自动恢复、fallback 或以缓存凭据续用。必要的任务失败按既有终态合同记录，历史只读仍可用。禁用当前连接后无生效模型，确定性比对、历史报告、人工记录不受阻。
- 保存/验证/启用/撤销使用稳定操作身份，服务端按部署、actor、操作和 key 绑定请求，响应丢失后重放同一意图；异 payload 冲突。明确区分非秘密的 `operation_key` 与模型 API Key：浏览器可在按已认证 actor/operation 隔离的 sessionStorage 保存 operation_key、操作 ID、连接版本 ID 和验证执行 ID；不得包含模型 API Key、凭据引用、端点输入或材料。登出/账号切换立即撤下旧恢复 UI 并隔离查询，服务端重放仍复核 actor/权限；同账号重新认证可恢复未决意图。刷新只读，不自动再次发送；需要重新输入凭据时仍核对原意图，不能生成重复版本或重复验证。未知状态下明确区分“查询原操作”和“确认重试原意图”，不能把可能首次提交的动作写成纯查询。
- 若运行时只能改共享模板且无法证明旧任务版本隔离，本切片的“实际启用”保持 BLOCKED，先提出显式停新任务/排空的方案变更，不能自行降低旧任务合同。不得为通过试验增加第二调度器、共享热重载、任意网络权限或模型 fallback。

#### 界面与验收

AI 设置展示当前生效版本、待启用版本、各验证层结果与启用/禁用动作；区分未配置、未验证、验证中、验证失败、准备启用、已启用、未知、已禁用和无权限。异常只提供与真实恢复合同一致的下一步；非管理员不显示秘密配置。保留中英文、明暗主题、键盘/焦点、reduced-motion，1366×768、1920×1080 与 390px 无整页横向溢出，提交有立即可见反馈。首页 AI 工作区和核查/报告的整体布局属于 EXP-UX-03，本片只提供其必要状态/绑定接口。

- AC02-1：Admin-only 配置/验证/启用/撤销，其他用户读取脱敏状态；越权、账号切换、晚到响应和认证失效正确。Key 不回显、不进入浏览器持久存储/日志/任务公开输出；Secret 失败或恢复缺失拒绝使用，相关审计不含秘密。
- AC02-2：版本不可变，至多一个待启用版本；保存、验证、启用独立；同 key 丢响应恢复、异 payload、并发启用、过期预期版本、验证中修改/替换和进程中断不会重复建立版本或错切生效指针。
- AC02-3：固定合成验证分别证明连接认证、目标任务能力和执行绑定；DNS 多地址/变化、重定向、metadata、不允许目标、协议/凭据/Runner 漂移使旧验证失效；验证流量与实际调用执行同一保护，无自动 fallback/真实客户外发。
- AC02-4：隔离真实 Pi + agent-compose + PostgreSQL 使用两个可区分连接版本：版本 A 任务建立后启用 B，新任务实际使用 B，A 的后续 turn/恢复仍使用 A；核查和报告分别有真实执行回执。仅设置读回、mock 或 API 200 不足以证明实际使用。
- AC02-5：启用失败/未知保留原指针；撤销 A 后 A 不再发起后续请求，B 不受影响；禁用当前连接后新 AI 任务被拒绝，确定性比对及历史/人工操作继续。原任务、旧失败、报告与已发布业务事实保持。
- AC02-6：旧环境连接的显式接管成功/失败、已有任务/未知 Session、服务重启和凭据引用恢复覆盖；普通设置访问不导入或修改模型。没有已证实的安全版本绑定不得展示启用成功。
- AC02-7：设置页正常、失败、无权限、未知恢复及三个宽度/键盘/焦点/双语/明暗/reduced-motion通过。沿用本轮性能口径：同设备/固定浏览器各5次，本地反馈≤100ms、不新增>200ms动作长任务，可比交互中位数不恶化20%以上；模型/服务端耗时单列，无基线能力不伪造before。

先执行隔离的非客户版本绑定试验并固定证据，再实施完整设置链路；不能先铺页面后把未证实机制标为可用。此次规格/Issue衔接不修改既有8080、B0/400、现场模型/执行器、OMP配置或已有业务结果；隔离本地固定响应端点可证明路由和恢复，但不冒充真实模型语义。真实 Provider 的目的地、材料与调用另行固定授权，不能借本节扩大既有出域例外。实现、真实模型验收、提交/push/PR、合并、部署和关闭分别记录；Standards/Spec 两轴审阅与独立业务验收分开，保留 PASS/FAIL/BLOCKED/NOT_RUN。

### EXP-UX-03 首页、资产和报告中的可见 AI

#### 目标与复用范围

从固定项目/已发布 Run 的首页，进入有依据的单资产核查、人工记录与独立 AI 分析报告。复用 WorkspaceOverview、固定资产 lineage、AiInvestigationPanel、ManualReviewPanel、AnalysisReportsPanel 及其既有请求/查询/恢复接口；不重建引擎或改变领域事实源。首页“本轮 AI 解读”导向现有 Analysis Report 面板，清楚区分“打开/查看”与“生成”；打开入口不代表提交任务。单资产快捷问题复用已有追问合同，仅填入明确的静态问题，提交仍是单独动作，不预填人工记录。

- “生成本轮解读”使用现有 Analysis Report 的有界材料与权限合同，固定 Project/Run/Report 身份；不把旧 governance draft 的占位会话作为解读引擎，不重新启用 v2 下禁用的旧路径。权威数量来自确定性事实，不由模型重算。

- 报告继续区分 AI 原稿、人工编辑与确认版；材料变更醒目提示，新材料需要新草稿，不能悄然改写旧版本。人工记录不关闭 Finding，不把解释或人工意见变成权威事实。

#### 身份、权限与恢复

页面打开、刷新、导航、切项目/Run/资产及快捷问题预填均只读或本地编辑，不创建 AI 任务。真实调用仅由显式发起/追问/生成操作触发，继续复核服务端 Operator 权限、材料白名单与预算；Viewer 只读，不显示可提交的写动作。模型状态的 ready 只表示连接就绪，不代替 Project 角色或材料许可。

组件与请求缓存、恢复身份按认证 actor 和固定业务范围隔离；切换账号、权限失效或范围变更后撤下旧编辑/恢复 UI。旧请求晚到不得覆盖新范围、写入新账号缓存/恢复存储或选择新的结果。已有幂等 key、未知启动查询、明确恢复与人工再试语义保持，禁止以换 key 隐藏未知结果，旧失败不改写为 PASS。

历史记录展示其自身已持久化的非秘密连接版本身份；旧 NULL 记录明确标作 legacy，不使用当前模型标识回填。允许仅为此向已有核查/报告读取 DTO 增加 nullable connection_version_id；不新增 Secret/端点读取权限、不解密、不迁移旧数据。当前连接身份与历史记录不同应可辨认，不能暗示旧结果由新模型产生。

模型失败时保留事实、引用、人工操作和历史确认报告的可用性；诊断入口与服务端的真实恢复合同一致，不把页面刷新说成重试，不显示假成功。

#### 验收标准

- AC03-1：首页首屏可见 AI 区、模型状态及到固定 Run 解读/资产核查的明确入口。首次打开、刷新与范围切换不发 AI POST；无模型和状态错误仍能读事实。

- AC03-4：项目/Run/资产/账号切换、刷新、晚到响应、未知请求恢复与失败重试实测不串线、不重复建立任务、不改写旧失败；无伪流式进度。
- AC03-5：报告原稿/编辑/确认及新材料提示保持；人工记录不关 Finding。历史连接版本和 legacy 身份准确，不使用当前模型伪造历史身份。

验证使用隔离的两个可区分资产、固定 Run 与历史 Run，覆盖正常、模型失败/缺失、Viewer、晚响应、材料变化与同 key 恢复。API/数据库、真实 Pi/控制面、模型语义、浏览器体验分别记账；本地固定响应仅证明路由、材料/状态合同，不证明模型语义。真实外部 Provider 的目的地与合成材料须另行固定授权，不能借现有例外外发客户数据。Standards/Spec独立审阅与业务验收分开，保留 PASS/FAIL/BLOCKED/NOT_RUN。

非目标：全库聊天、AI 自算权威统计、自动风险打分、自治扫描/写回、批量自治核查、AI 记录预填、模型市场、新工具/新材料范围，以及 EXP-UX-04 的全站统一和最终交付。确有有界材料接口缺口时只做本节所需最小增量，不改变已接受 ADR 的网络、认证、审计、不可变事实和人工确认边界。

### EXP-UX-04 主流程一致性与最终交付验收

维护者在 EXP-UX-01–03 完成后批准进入本阶段。范围是已有项目准备、概览、资产核查、AI 设置、报告五类页面的一致性收尾与独立交付验收；沿用已有青绿主题、组件、原生语义与布局，不重设计、不补未来产品功能。授权包含规格/Issue衔接、本地实施与隔离合成验证；业务代码发布、合并、部署与关闭仍需后续明确授权。保护现有8080、模型及历史数据和其他工作树。

#### 范围与行为约束

统一已有上下文、同角色按钮、状态反馈、间距和技术详情规则。只修有实际证据的局部缺口，优先复用共享 Button/Card/Alert/details 与现有 tokens，不引入新依赖、动画平台或通用工作流。准备页清楚区分已接受/当前选择/本轮固定，概览保持服务端确定性统计，资产与报告固定 Project/Run/Resource 范围；AI设置仍为独立部署级权限和版本生命周期，不能伪装成某项目专属连接。

四类关键交互为创建/首轮提交、输入接受或拒绝、固定项目/Run/资产导航、AI显式提交及人工保存确认。提供与真实状态一致的立即反馈，保留未知状态、原幂等恢复与失败记录；无持续装饰动画、伪进度/流式输出、未知转零或自动模型调用。导航与刷新只读，Viewer和非管理员权限、资料许可、历史连接身份、AI原稿/编辑/确认边界不变。共享组件修复须检查全部调用方；不改后端业务、数据库Schema、Runner或出域范围。

#### 验收标准

- AC04-1：五类页面使用一致且可辨认的上下文、主次动作、状态和可展开技术详情；已实现且符合要求的部分保留，缺口有修复前后证据。
- AC04-2：上述四类交互显示真实反馈，未确认和失败均有现有合同允许的恢复路径；不新增自动任务或伪成功。

- AC04-4：中英文、明暗、键盘导航/焦点恢复、非颜色状态、reduced-motion 可用；禁用动效不影响完成动作或读取状态。

### EXP-EVO-01A 客户原生台账与人工派生版本

维护者于 2026-09-15 在 EXP-EVO-00 接管回执后明确批准本切片。本节固定该切片的目标、设计与验收合同；**新增行为尚未实现或验收；维护者已进一步授权本节规格提交/推送、正式 Issue 衔接、隔离本地实现及合成验证**。配套 [ADR-0018](../adr/0018-customer-ledger-derived-upload-versions.md) 仅接受客户台账与派生输入的决定。规格发布、正式任务与业务实施按本次授权边界分别衔接，不预写不存在的 commit/Issue。01B/01C/02 及后续外部写回不随本节批准。

#### 范围与继承

用户可以通过独立客户资产台账页面查询原生行、完成最小新增/更正/归档、责任与标签管理，并明确变更只影响新版本与后续新批次。页面无需已发布 Run 或 Resource，不从比较或报告样本拼表；复用既有 XLSX 导入、选择、准备/确认、治理执行、历史阅读和 UI 组件。

本节允许其所需独立页面和后端增量，不沿用 S1/EXP-UX-04 对各自任务“不新增页面/不改后端”的局部范围限制；不改那些任务的历史授权与验收。权威事实与时间、人工核查/报告、EXP-UX-01 输入确认、ADR-0005/0008/0013/0016 继续有效，旧 Resource UUID/唯一键、Run、快照、比较、报告与引用不改义。

#### 原生查询与画像

- 提供独立列表、详情、版本回看、服务端筛选/分页；读取先解析明确 CustomerUpload/台账 Revision，翻页不静默切到新版本，显式刷新才换版。完整原生行总数、规范 IP 数分别命名，不使用当前页、Resource 或报告样本推算。
- 完整读取当前支持字段，不能以只含 IP 的 Observation 重建整行。当前合同包含资产 IP、起始/结束端口、是否 Web、Web URL，以及支持的服务类型、资产负责人/所属部门、端口负责人/部门、序号等；保持既有校验/warning，不将未知列自动升级为字段。原文件完整保留，派生版本说明仅物化已支持字段。
- 重复 IP 行保留独立稳定条目身份，可有不同端口/Web/责任；更正一行不改其他同 IP 行，身份不能使用可变排序号。原上传字段、人工更正值与本地标签/责任确认分层，后者固定自己的 Revision/作者/时间，不覆盖或冒充客户原声明。列表与详情的输入/管理版本保持一致。
- 明确展示所读版本、来源、截至时间、当前选择及与固定 Run 的区别；损坏/解析失败不能降级成空表。无匹配、无已接受输入、加载和请求失败分开。
- 客户部分 IP 画像展示同 Project 规范地址、该版本相关行、责任/标签和编辑历史，无 Resource 仍可查。首片沿旧 Project 地址空间并标示 legacy 范围，保持 mapped IPv6 折叠，不新增 namespace/跨来源关联模型、不伪造云图/活动/风险字段或第四份主表。

#### 人工版本与派生 CustomerUpload

- 人工保存追加不可变 Customer Ledger Revision，固定父版本、稳定行身份、变更、作者、时间与理由。输入字段变化物化人工派生 XLSX，重新通过现有严格 CustomerUpload 接受链路；仅标签/关注/本地责任确认变化追加管理 Revision，不为此造新输入。更正客户声明责任字段与本地责任确认在界面及存储上分开。
- 父上传/Artifact 原字节、文件名、Hash 和来源不改。派生输入使用明确人工来源的展示名称、实际字节 Hash、固定 Profile/生成合同；父链与 Revision/provenance 在 PostgreSQL 不可变保存，不仅写文件名或被忽略的额外列。派生文件不是客户系统返回，也不是 SourceInstance。
- 生成前校验编辑值，生成后再执行完整 ZIP/OOXML、资源上限、行/字段/IP/端口/Web 校验。复用已安装依赖和现有校验器，必须证明当前支持字段无损物化，不通过宽松解析或前端校验绕过；不声称派生文件与原文件逐字节相同。
- 归档只从新版本有效行排除条目，不删除旧版本。保留至少一条有效记录的既有合同：归档最后有效行/零条派生输入须在提交前拒绝并保留原版本和当前选择，不造占位 IP 或假成功；空客户输入另需批准合同扩展。

#### 原子保存、幂等与恢复

现有上传接受与选择是两次提交，浏览器串联旧接口不能冒充原子保存。新增最小领域事务入口：有界校验/暂存派生字节后，锁 Project 并重新鉴权，核对预期当前上传、父 Revision 与 Profile，在同一数据库事务中接受派生输入、保存 Revision/provenance、更新当前选择并追加脱敏审计。仅管理字段变化不改变输入选择。失败保持原选择，不留下可用半版本；文件失败只处理本次未引用对象，不删除父 Artifact/其他任务文件。可抽取现有接受逻辑的事务内部分，旧调用方语义保持，不建第二套校验器。

人工幂等按 actor/Project/操作/key 绑定规范化请求，独立于文件内容去重：同 key/payload 返回原结果，异 payload 或陈旧父版本明确冲突；同 key 已成功重放不能因自身更新了当前选择而误报陈旧。并发更正不采用最后写入覆盖，编辑期间输入/Profile 改变须拒绝陈旧提交并保留编辑供重新确认。派生字节命中既有上传时可复用输入内容，但人工 Revision 仍有自身父链/身份；不能重写被复用上传来源，更不能把原始上传改标为人工生成。

提交前保留按账号/Project/操作隔离的非秘密恢复身份；未知/丢响应查询或显式恢复原意图，不换 key 重写，不因刷新自动 POST。不得在浏览器持久恢复存储放上传字节、整行客户信息或秘密。切账号/Project/版本后撤下旧编辑/恢复 UI，晚响应不能覆盖新范围。原有导入/选择入口改变当前输入后，人工页面必须重读新基线，不能将旧行索引/管理值误关联到新文件。

#### 新 Run 与旧历史

GovernanceRun 继续只固定现有 CustomerUpload ID、raw hash、Profile ID/version，以及原 CloudAtlas 和 NetFlow pin；Customer Ledger Revision 不是新 Run 输入类型。人工出处经不可变关联追溯，旧 canonical input 不声称直接包含新 origin/Revision。首片不扩展报告材料合同；新报告/AI 若以后需要管理字段，须在其获准合同中显式固定管理 Revision，不能实时拼入旧报告。

保存只更新当前版本，不自动 Run、不关闭 Finding。用户下一次明确确认新输入，确认后漂移沿旧合同拒绝；同 key 恢复不换输入，旧 Run Retry 仍要求满足原固定输入条件，用新输入要明确 Rerun。只有新完整 Run 按旧确定性规则验证差异解决。已发布 Run、快照、比较、报告、人工核查和 AI 原文/引用保持旧身份/内容，历史失败和未验证结果保留。

#### 权限、界面与验收

读取沿既有项目读取角色；写入限定 Project Operator 或全局 superuser，Viewer/仅 Approver 不获得写权，不新增 Project Admin。后端每次复核项目、账号、归档/撤销、输入/行/Revision 的归属。归档 Project 拒绝新编辑，历史按原授权可读；跨项目访问/重放不泄漏。模型不可用不影响台账和历史读取。

界面区分未选择、加载、无匹配、旧版、输入非法、冲突、保存中/成功/失败/未知及无权限；反馈对应真实操作，无伪进度。保留中英文、明暗主题、键盘/焦点、reduced-motion；1366×768、1920×1080、390px 关键动作可达，无整页横向溢出，表格可局部键盘滚动；技术身份默认收起但完整可读。

### EXP-EVO-01C NetFlow 原生活动账与 IPv6 候选

批准依据：2026-09-16 维护者明确要求继续“授权范围内的 NetFlow 原生 IPv6 候选”。本片承接 EXP-EVO-00 的 5.4/5.5 与 01C Seed，固定下列最小实现合同；继承已交付 01A/01B，不批准 02 或外部纳管。配套 ADR-0020。

#### 目标、范围与事实

1. 独立 NetFlow 活动账直接读取本 Project 已接受 Dataset 的固定规范化 Artifact，校验 tenant/Project、Dataset、原始/规范化 hash、合同、记录数与字节完整性。无 Run、Resource、客户上传或云图快照仍可阅读全部有效端点，不从报告样本或旧受管聚合反推全集。读取为有界、无写入的确定性投影；不另建资产主表或第二调度器。不支持的合同、缺文件、哈希/行数漂移或超出明确处理上限必须显示投影失败，绝不返回截断的“完整账”。
2. 沿 ADR-0005 规范化，标准 mapped IPv6 折叠 IPv4；非法/zone 地址不进入候选，旧已接受材料中出现此类值须拒绝投影而不是静默修正 Dataset。每条有效流的两个不同端点分别计一次，自环端点一次；合法重复记录各自计数。保留 src/dst/both 角色、协议、可证首次/最近时间、有界 source_record_key 引用及原始 Artifact 身份；未有时间保持未知，原文本通过源行引用追溯。分页、筛选、计数基于完整投影，而非当前页面。
3. 每个 Dataset 的范围绑定须由全局 Admin 显式追加不可变修订：稳定网络空间标识、明确 CIDR/单地址、采集来源/位置、证据出处、探测视角 PUBLIC/INTERNAL/UNKNOWN，以及 CONFIRMED/UNKNOWN/CONFLICT/REVOKED 状态。首版一次绑定一个明确空间；来源混合且不能确定唯一空间时保留 CONFLICT，不猜分配。`legacy` 表示明确对应已有 Project 空间，其他命名空间互相独立；名称为身份标识，不提供原地重命名。多个 CIDR 在同一已确认空间重叠可以合并判定，不能据跨来源相同地址推定同空间。新 Dataset 必须重新确认，不自动继承来源/授权；空间更正追加修订并形成新身份，保留旧历史。

6. 画像固定 Dataset、范围/管理修订和可选客户版本/云图快照，来源原生事实可独立显示。无其他来源时明确未提供，不伪称该 IP 未报备/未监控；完整已选版本无行仅表示该版本未观测。仅当前仍有效的已确认 legacy 绑定，且可选云图快照也满足 01B 的当前 CONFIRMED_LEGACY 合同，才复用该明确 Run 的历史 Resource/处理入口；未知或其他 namespace 不合并历史。撤销后历史评估可回看，但不能继续表示当前候选资格或关联许可。风险继续 NOT_CONNECTED，画像不调用 AI。

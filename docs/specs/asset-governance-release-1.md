## 已批准要求

### 工作流

治理人员以 IP、发现类型和业务状态识别问题。看到各来源观测、数据时间和活动线索后，对明确的单个资产或发现手动发起 AI 核查；可在同一 Project/资产/已发布基础 Run 范围内追问。保存人工结论；该结论尚不代表 Finding 已解决。后续成功且兼容的对账验证原差异已解决、仍存在或证据不足。可手动生成一次对账的分析报告；无核查时如实说明缺口。Viewer 只读，不能触发模型、写入人工结论或确认报告。

### 权威事实与时间

PostgreSQL 与确定性处理仍是结构化业务事实来源。AI 或人工说明不更新 GovernanceRun、SourceSnapshot、IPSourceComparisonFact、Finding 或已有 GovernanceReport 的权威内容。核查固定 Project、Resource、基础已发布 Run，以及相关 Finding（若从发现项发起）。追问延续该范围，不静默切到 latest。新的只读查询记录查询时间与引用身份，不得覆盖原 Run 快照或混入原 Run 统计。未执行、未成功或越权的查询不能产生肯定性新事实。失败记录可引用为局限，不能当作成功 Evidence。

### AI 核查

Pi 执行受限模型会话，模型只调用白名单工具；至少包含明确范围内的系统事实/历史读取和既有 CloudAtlas 的 OctoBus 只读能力。每个工具参数和返回值由服务端复核授权与范围。模型不得获得数据库凭据、应用 Secret、任意 Shell/SQL/URL、Artifact 原始文件或外部写能力。核查和每轮追问有可观察状态与部署固定的工具/数据量/时长上限。未知 Session 不得解释为成功或自动另开重复执行。请求重放保持幂等；失败后的再次人工尝试保留原失败记录。不得以自动换模型/Provider 或无界 retry 强行完成。输出分清事实、解释、缺口和建议。引用检查验证身份和范围；有引用不等于语义正确。

### 人工记录与后续验证

人工记录保留作者、时间、关联对象、基础 Run、结论及待验证事项；更正追加版本并保留原记录。验证只回答原一致性差异是否被后续事实解决。关联同一 Project/Resource 的后续成功且兼容 Run：满足既有确定性关闭规则才显示已验证解决；仍存在差异显示未解决；不足以判断则显示证据不足/待验证。NetFlow 的 ACTIVE、零记录或缺失均不单独关闭 Finding。已发布的后续 Run 与验证结果不可重写；再出现失败 Run 时保留原成功验证身份。

### 分析报告

用户手动生成/更新草稿，以一个明确 Run 的完整确定性摘要为主体，可读取有界历史与已保存核查/人工记录。模型不自行汇总权威总数，不编造业务归属、严重性、因果或已完成动作。保存 AI 原稿与人工编辑；人工确认是独立动作。统计、身份和引用不可当作随意修改字段。新材料出现时，标题/主要操作区醒目标明未纳入此版本，并提供生成新草稿入口；完整旧版本保持可读。新草稿不自动确认，也不自动覆盖已有草稿/确认版历史。

可读性修订（#220）：正文简体中文、结论先行、短段落与业务语言；固定材料和引用中保留完整追溯身份；统计只复述权威事实；区分当前差异、历史积压及无数据/零风险。

历史归属修订（#221）：正文按资产、按 Run 说明不同轨迹。不得把某一个资产的生命周期套用于整组资产。结构化引用合法不能代替这项语义。截断历史须标明缺口。

### 页面与权限

默认阅读顺序：资产情况 → 核查进展/验证 → 分析报告。“查看依据”保留技术追溯。列表主标识为 IP、发现类型等业务信息；完整 ID/Hash 可复制，短显示不改变引用身份。窄屏与键盘可用。Operator 执行核查、记录和报告编辑/确认；Viewer 只读；Admin 保持既有显式权限。每个服务端操作复核项目授权。保留简体中文/英文、明确的空/加载/失败状态，以及确定性报告的独立可用性。

### S1 概览入口与业务阅读

#### 行为

1. **核查入口。**概览提供“台账未登记，外部已观测且有活动”（`classification=cloudatlas_only`、`netflow_status=ACTIVE`）和“台账已登记，外部未观测但有活动”（`classification=customer_upload_only`、`netflow_status=ACTIVE`）两个快捷入口，复用已有三源比较及筛选，从第一页开始并清除遗留资产选择。它们仅表示核查线索，不构成评分、严重性、已确认风险或完整风险清单；保留“查看全部资产与差异”。
2. **计数边界。**数字必须来自明确 Project、Run 和完整筛选范围的权威结果。不得使用当前页行数、截断血缘节点或两个独立维度总数推导交叉数量。S1 概览快捷入口不显示数量，也不新增交叉计数请求；已有完整批次摘要及比较页服务端筛选总数保持各自范围说明。缺失、UNKNOWN、无匹配和请求失败不能混同为零。
3. **范围连续。**路径为概览 → 带条件三源比较 → “查看资产并核查” → 已有 `/projects/{projectId}/runs/{runId}/lineage?resource_id={resourceId}` 单资产范围。该页业务事实优先，复用已有 AI 核查与人工记录面板；原有血缘、节点和路径按需展开，不新增页面或图组件。从概览到核查保持同一 Project、Resource、已发布基础 Run，返回比较保留筛选和页码。未选择批次时可沿用已有解析并固定到 URL 的行为；显式历史批次不可被 latest 替代，也不能用 latest 资产弹窗的事实承接历史阅读。范围不匹配、不可用或读取失败时，不展示其他批次事实，不允许基于错误范围发起核查。资产入口不擅自绑定 Finding；明确发现项入口沿用其 Finding 身份。
4. **业务标识。**默认以 IP、可信且已存在且属于该范围的资产名称、差异类型、来源和时间组织阅读。名称缺失时只用 IP，不伪造名称、不引入新数据源或跨批次拼接。批次以时间为主标识；显示标签不作为身份 key。来源时间、活动证据局限、读取失败及资料缺口留在业务阅读区。
5. **技术追溯。**演示涉及的概览、比较、单资产核查、批次选择、客户上传/配置、运行记录、AI 核查及分析报告默认收起 UUID、Hash、Profile ID 及完整引用身份。详情可展开、完整读取、复制且键盘可操作；折叠标题本身不暴露长技术串。底层字段、选择值、请求参数、引用和校验不变。复用已有完整值复制和原生折叠能力，不建立新的通用身份框架。人工记录及确定性报告已有折叠结构继续复用；分析报告保留 B0 已修正的确认正文与 AI 原稿分离。
6. **既有业务边界。**进入页面不触发模型；权限、人工记录不直接关闭 Finding、后续验证不改写基础批次等既有约束不变。Viewer 只读。AI 自由文本中的英文或技术串不通过正则删改；收起结构化元数据不代表解决自由文本可读性。若其仍干扰演示，单列未通过项，不冒充解决、不自动扩为模型改造。

#### 验收

- **AC1 — 两个入口可用：**使用 B0 首轮成功批次，两个入口分别能找到 `192.0.2.46`、`192.0.2.20`，并进入对应资产、同一基础批次的核查区域。页面打开不触发模型。
- **AC2 — 历史范围不漂移：**后续补齐台账的成功批次已存在时，从首轮进入仍显示首轮差异；刷新、前进后退、分页和核查请求保持身份。显式切换批次后才读取新批次。跨项目、跨资源或批次不可用时 fail closed。
- **AC3 — 没有伪总量：**快捷入口无数量；比较结果超过一页时，总数来自服务端完整筛选结果，不随分页变化。无匹配、缺失、UNKNOWN、请求失败分别呈现，不统一显示为零。
- **AC4 — 默认阅读无结构化技术身份干扰：**上述演示页面默认以业务标识阅读；展开后能读取并复制完整 UUID、Hash、Profile ID 和引用身份，复制结果与原值一致。来源、时间、状态与必要错误说明不被隐藏。
- **AC5 — 可访问性与回退：**桌面及 390px 窄屏可完成入口、筛选、核查阅读和详情操作；键盘可展开、复制、返回，关键操作不被溢出隐藏；保留中英文及加载/失败状态。
- **AC6 — 业务与身份不变：**Viewer 不获得写权限；页面打开不产生模型任务；既有引用校验继续有效；历史核查、人工记录、确认报告及确定性事实不因展示调整被修改。

S1 以一张任务交付入口连接、演示阅读分层及保护检查。不扩大为整站重构；不新增评分、大屏、图组件、AI 底座、同步接口、导出模块、资产名称数据源或 S2/S3 能力。开发验证与下一会话独立业务验收分别记录；源码、mock 组件检查或 CI 通过不等于 B0 实际材料的 S1 业务验收通过。

### 实现与验收约束

正式实现必须运行真实 Pi、只读工具、agent-compose 和数据库；模拟原型不能代替功能验收。真实客户数据不得因此出域。复用现有业务 reader、项目授权、报告校验和 agent-compose 生命周期。

## 明确非目标

- 批量/后台自动核查、对账后自动生成 AI 报告、独立周期汇总报告。
- 自动扫描、Retry/Rerun 作为本 Spec 新能力、外部写回、自动处置、分派审批/工单闭环或人工直接关闭 Finding。
- 新增 CMDB/扫描器等数据源、完整通信拓扑或未经事实支持的业务归属。
- 真实客户数据向百智云外发、客户生产验收、第二套调度/事实库、多实例 HA。
- 将原型直接合入正式入口、未要求的新导出、顺带修复既有 XLSX 兼容缺陷。

## 产品结果与责任

Exposure是外部暴露核查与处置产品。云图在约定版本/授权空间/接口或正式导出范围内提供的完整资产、服务、风险及依据同步本地；用户在Exposure内完成列表、搜索、详情、风险关联及依据阅读。外链可作诊断，但不作为核心阅读必经步骤；摘要、计数、iframe、实时详情透传均不能代替本地同步。

产品区分以下含义，不要求提前建立同名表：

| 概念 | 权威及不可混淆边界 |
|---|---|
| 来源资产/服务 | 云图源字段及来源身份；独立于旧Project内IP Resource，不能因同IP跨空间合并 |
| 云图原始风险 | 云图原始判断、等级、状态、时间与受影响对象；不得被本地AI或处置进度改写 |
| 暴露问题 | Exposure的核查结论、责任、待办/动作、复测及关闭依据；不机械一风险一问题，也不隐式合并 |
| 同步/核查/动作任务 | 固定范围、输入版本、操作者/执行身份和明确终态；失败、取消和未知均不能冒充成功 |

PostgreSQL保存Exposure本地权威业务事实；OctoBus仍是客户平台/云图外部边界；agent-compose仍是运行调度/隔离边界。内部平台维护内部资产，Exposure只读核查上下文；Excel只是兼容输入，不扩建内部CMDB。Web/cumora共用服务与权限，不共享可任意写入的数据库或复制问题状态。

## 新同步与本地阅读边界（实施仍须逐片授权）

1. **独立性**：不要求CustomerUpload、NetFlow、旧GovernanceRun/Resource或比较结果；GET/分页/详情只读本地，不触发云图/模型/扫描。第一条演示必须在无上述输入/历史的新项目完成。

3. **来源身份**：按经核实的来源空间和稳定对象身份幂等；未证实长期稳定、ID重用或关系键时不自动跨同步继承/合并。重复IP、风险先于资产到达、关系暂缺均保留，不错绑或丢弃。历史来源记录键不被重新解释成稳定对象键。

5. **发布和失败**：每个数据域区分最近完整成功范围和本次任务/局部更新；中途分页、鉴权、超时、重启失败不清空旧完整结果，不把部分数据标全量成功。各域独立时间不能冒充同时快照；错误及陈旧状态对用户可见。
6. **变化和关闭**：增量未返回不等于删除；全量消失也先核对权限/过滤/范围与真实删除语义，保留历史及未再观测/待确认。既不自动修复源风险，也不自动关闭本地问题；交办、反馈处理、复测通过是不同状态。
7. **依据安全**：结构化呈现约定详情，必要证据/附件本地受控存储，不以大段原始JSON交付。抓取仅限确认的来源、类型/大小/重定向及网络边界；防SSRF、脚本执行、恶意文本和提示注入。真实凭据/原IP/未脱敏响应不得进入Git、Issue、模型或审阅材料；不默认持久化全量原始响应。
8. **权限和保留**：页面、直调API、导出、附件、cumora均复核当前Project/SourceInstance/用户数据范围；Viewer只读。权限撤销即时阻止读取/执行；停用连接只停止同步与撤销历史访问是不同动作。具体保留期限/删除依据/撤销后的存储处置须明确批准，未定不能无限留存；保留数据不代表用户仍可见。
9. **运行和恢复**：复用已有PostgreSQL事务/锁/幂等、agent-compose固定执行身份及未知结果保护；同步任务有可恢复的持久边界，不依赖网页持续打开。不得引入第二套调度器或以超时猜Session已终止。新任务不改旧Run单活跃/Retry/Rerun规则。

### 本地身份、读取与关联

1. **域版本而非假稳定实体**：发布版本固定Project、来源空间/合同/指纹、域、过滤、排序、读取区间和源ID。源ID只标识该域版本内记录；长期稳定/重用未证实前，不跨版本自动继承标签、责任、风险或外键。这遵守ADR-0021，不以一次ID不重复解除其限制。
2. **两个不同的幂等问题**：相同操作者/项目/来源/请求内容的同一幂等键重放，返回原任务而不再调度；键相同但内容不同拒绝。新同步可以形成新发布版本，列表只读选定版本，不因保存多个版本重复显示；这不是跨批次源对象幂等更新。
3. **关联是查询事实**：IP详情可展示同一来源空间、各自选定域版本中规范化IP相等的端口，明确标示“同IP匹配”及两个域的版本/时间。匹配多条则保留全部，缺IP对象的端口仍在端口列表；不创建声称供应商确认的稳定外键，不跨空间拼接。
4. **最小Interface**：项目/来源范围内提交手动同步、读取任务状态、分页/筛选本地IP或端口、读取固定域版本记录详情；HTTP路由和客户端沿现有FastAPI/生成客户端模式落实，不复用旧cloudatlas-ledger端点改变其Run合同。所有列表/详情GET仅查本地，不调用OctoBus、云图或模型。
5. **权限**：复用现有项目角色，当前Operator/Admin可发起同步，既有读取角色只读；归档项目不允许新任务但仍按权限只读。每次读取/执行都复核Project及来源数据访问范围，撤成员或撤数据访问立即拒绝，包括固定版本深链。前端收到访问拒绝后清除相应缓存/详情，不以旧缓存降级显示；不宣称撤回用户已经看到或另行保存的内容。单纯停同步不隐式撤历史阅读；来源不可达也不成为本地阅读前置。

### 手动同步与失败发布

- 复用agent-compose的调度/隔离/Session生命周期，PostgreSQL持久记录新同步任务及域进度；不伪造GovernanceRun，不在HTTP请求或浏览器生命周期中跑完整同步，不引入第二调度器。
- 新手动请求采用固定范围的有界采集批次，不采用增量游标或自动补读；仍给出page size、两域合计最大页/记录/响应体/时长预算，并发1、无自动源调用重试。`max_pages >= 2`且`max_records >= 2 * page_size`，即累计预算至少容纳两页及两页配置大小的记录，否则在创建任务前拒绝。
- 两域公平保留页额度：可读页额度为`min(max_pages, floor(max_records / page_size))`；IP获得向上取整的一半，端口获得其余一半。串行按IP、端口轮转，每轮各读一页，已完成或封存的域跳过；未使用的域额度不转借。每次任务均从第一页开始，不把上次页码当可靠续传游标。
- 固定排序请求（采用公开声明的`-id`；实际不接受则失败，不静默换序）。检查响应页码/size、非负total、记录身份及跨页重复；total变化、重复ID、提前空页、超出total、超过已获准预算或结构异常均停止，不丢坏行凑成功。源total大于批次预算不再直接拒绝合法首页，也不把该total当本地已保存数量。
- 每域先暂存。所请求范围确已读完，或该域正常读完预分配页额度且至少取得一条合法记录时，持久封存已验证页数、记录数、源报告total和停止原因；再复核执行身份、权限及指纹，在同一事务发布不可变域版本和最新可读指针。累计记录数等于一致total时才标记完整；正常到额但未读完的版本标记非全量。合法完整空集可发布0条，未读到有效页不是成功空集。
- 两域都发布且都完整，任务为完整成功；两域都发布但至少一个非全量，任务为“批次完成（非全量）”，不得沿用完整成功标签或伪装失败。一个域发布、另一个明确失败时仍为部分失败。一个域封存后即可读取，不等待另一个域读完；首次未发布域显示未同步/失败，不显示成功0条。
- 来源异常、停用、撤权或指纹漂移停止后续请求，未封存暂存不得发布；已发布版本不因另一域后来失败而被抹去。任务未知不产生替代Session。仅在原Session权威终态明确且当前权限/指纹仍有效时，恢复已经持久封存的域发布；不能凭“已有一些记录”或本地超时封存未知结果。
- 默认列表读取最新可读批次，同时单独提供最近仍可读的完整版本入口。非全量批次可成为最新可读版本，但不得删除、改写或冒充最近完整版本；新失败不移动该域可读指针。每次请求仍必须提供未来的`retain_until`，完整与非全量批次均继承该截止；到期不再发布，列表返回EXPIRED且无记录、固定记录详情拒绝读取，不自动回退旧缓存。历史完整版本也受当前权限、空间与保留期限约束；清理范围仍限于执行许可指定的新读模型数据，不触及旧Run/报告。
- 不跨批次拼接成假全量、不继承稳定对象身份、不把未返回记录当删除或修复。旧固定版本深链保留；已持久化的旧任务继续按创建时的完整发布合同执行或对账，新语义不得使旧失败暂存突然可读。同键恢复仍返回原任务，不能借版本升级重新调度。

# ADR-0026：独立 NetFlow bulk 外存计算与版本化查询

状态：已接受。2026-10-13 维护者指定默认架构并明确授权规格发布、建单及本地实施。精确合同以同版 [NetFlow bulk V1](../specs/netflow-bulk-v1.md) 为准。

## 证据与决定

[当前代码审计](../work/netflow-bulk-audit.md) 确认旧入口有界、小文件逐行SQLite统计、分析适配10万行及新版结果全bundle加载。单纯调高上限会把瓶颈转移到API内存和读取延迟。

复用 PostgreSQL、权限、审计、不可变Artifact、Context/Analysis及agent-compose Session；新增独立bulk源码、Parquet明细与DuckDB外存工作区。DuckDB仅确定性计算，可丢弃重建，不承载业务权威或另设调度器。任务lease/checkpoint是既有执行的恢复与防重协议。保留0.4.0适配器/wheel/footprint及原处理、计数合同。

新合同窄扩展 ADR-0020/0021 的源侧处理实现和 ADR-0024 的可选辅证读取后端；不改变其身份、未知、权限或核心两源独立性。旧活动账/旧V1关联不接受bulk；不放宽有界扫描。新bulk按独立policy呈现准确能力，不宣称已复刻旧组件全部复核规则。ADR-0023独立保留任务仍不纳入，不回填旧期限、不删历史。

使用受控快照+ready身份；保守精确导出记录去重而非网络事件去重。完整键外存比较、确定性样本、服务端索引查询取代全量内存集合。增加文件/事务双阶段故障恢复、资源预算和实测成本；这是支持容量验证的必要复杂度，不承诺尚未执行的TB规模。

不采用Kafka/Spark/Flink/Kubernetes、分布式集群、Bloom最终判据、chunk内去重相加、默认多Agent或逐条模型判断。后端Python不降级；依赖/镜像兼容实测后锁定。未来跨数据集增量去重需要新的合同及验收。

## 验证与发布边界

同版Spec AC-B01–08。只合成/授权脱敏数据，分级压测，报告RSS/spill/IO/恢复/查询延迟。规格发布和本地提交不等于源码远端发布、合并、部署或TB验收；现有生产环境保持。

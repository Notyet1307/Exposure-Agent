# ADR-0024：核心两源比对与独立 NetFlow 辅证

状态：**已接受**。维护者于 2026-10-08 明确批准候选 `554e80e8ce172f6b208e2dae85deeec7daf17816` 的本 ADR、V2 Spec 与任务拆分（含新辅证绑定显式截止），授权规格文档正常发布及固定版本建单。准确行为与验收只在 [V2 Spec](../specs/product-logic-convergence-v2.md) 定义；不包含业务源码远端发布、部署或真实来源/模型调用。

## 问题

现有 SourceCorrelation 可以 `netflow=null`，但选入 NetFlow 后，其地址进入主集合、其读取资格成为整份关联的依赖。仅把前端文案改成辅助观测，会同时造成统计与失败语义冲突。原聚焦 Spec N4/N7、API V1 §9及三源 V1 U2/U5必须继续解释旧固定结果。

## 已接受的窄决定

1. 新常规结果复用现有固定两源关联服务，以明确的新合同/用途标识区分 V2；C/A/确认范围/规则版本决定核心内容与统计。不复制云图为另一资产主表，不另建计算引擎或调度器。
2. NetFlow 仅通过追加的固定辅助身份绑定附加。按各自原权限、范围、实际期限读取原产物；绑定不保存敏感明细/自由文本，也不延长生命周期。新绑定须显式固定自己的未来截止，无隐含默认；不能超过已实现的可信上游期限。基线 Analysis 无TTL，不能冒称其已到期；绑定到期只拒读绑定的派生内容，不改变底层独立Analysis期限，不实施#287。N不可读或绑定到期清除辅证，仍有效的C/A核心可读。
3. 核心 C/A 任一必需输入不可读仍拒读。旧 V1 全部所选依赖、七组合计数及整份失败封闭继续；历史不自动转换、不删 pin、不从原始活动账恢复过期结果。
4. 普通入口用服务端明确范围内的最新常规成功可读结果，解析后固定身份；持久用途/发布状态/发布时间及固定ID，按发布时间和ID稳定排序。自定义历史、失败/未完成和迟完成旧输入不能占用当前发布；幂等和并发控制复用现有PostgreSQL事务。NetFlow采集范围另有可信持久声明/确认，current Dataset不能证明跨文件同范围；缺真实观测窗口时显示未知，不以处理时间替代。
5. 新导航以核心结果与独立数据为主，接入为设置，历史功能保留原义。客户版本仍由 #285/U3 与 ADR-0018 承载，18 类云图按 ADR-0021/0022 保留；不引入 CMDB 扩张。

## 适用与历史边界

本次只窄替代新 V2 的集合/可选依赖、普通最新解析与入口组织；原 ADR-0020/0021 的固定来源、身份与权限不放宽。ADR-0023 对独立结果生命周期和旧 SourceCorrelation JSON 引用的规则继续适用；新辅助绑定不得成为期限旁路。#287 的90天/清理实现不在本轮，不回填期限、不迁移旧记录、不清理数据。

## 取舍与验证

选择两源核心加最小绑定，可复用已有全集/证据 reader，并避免任意一个辅助材料到期使整个新核心失效。代价是显式区分 V1/V2、核心/辅证状态和常规/自定义用途，必须覆盖新旧交叉回归与迁移保留检查。直接修改旧 selection 或将 N 文本复制进核心都会破坏历史身份和保留边界，因此不采用。

批准本 ADR 与 Spec 不代表实现通过、远端发布或部署获准；需要正式 Issue 固定实际 commit。验收重点为 V2 辅证独立失效与 V1 整份拒读同时成立。

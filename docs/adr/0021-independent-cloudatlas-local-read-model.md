状态：**已接受，限下述新云图路径及产品边界；后续AI/处置替代仍为提议**（2026-09-23，[文档任务 #245](https://github.com/Notyet1307/Exposure-Agent/issues/245)）。维护者授权必要文档定稿与发布；不代表业务实施、真实读取或后续阶段已获授权。

## 保留的责任和恢复边界

- PostgreSQL仍是Exposure结构化事实权威；云图保留源判断权威，客户平台保留内部资产主责。agent-compose负责运行隔离与Session，OctoBus负责外部能力；不引入Redis/Celery/Kafka/Temporal或第二调度器。
- 成功发布的各数据域版本可独立保存，但必须各自显示时间/范围，不能宣称上游不存在的跨域原子快照。失败不清空最近完整结果；增量未返回、一次消失或权限变化不自动删除/修复/关闭。
- 连接停用阻止新读取；若项目成员或来源数据访问权限撤销，本地API、页面、导出及cumora一致拒绝。单纯“停止同步但允许历史阅读”和“撤销数据访问”必须区分；保留数据不等于仍有读取授权。
- 本地说明、优先级、责任/处置不覆盖源风险等级/状态。模型只在获准有界证据上给解释/草稿，不计算权威统计、创造来源事实或批准动作。
- cumora复用同一业务服务及任务身份；不共享可任意写入数据库、不复制问题状态、不借cumora自有基础设施为Exposure增加调度/事实源。
- 已共享迁移、旧Run/快照、Observation/Resource/Finding、报告字节/Hash、引用、模型配置及资格绑定都保留。新增存储如需Schema变化只用后续新增迁移，并核验旧程序/回退兼容，不重写历史。

## 取舍与批准范围

只改展示无法获得风险合同或离线详情；扩建旧Run并伪造客户输入会继续绑定三账；全量复制云图数据库则超出需要。选择最小本地来源读模型，代价是需要显式同步身份、完整性/失败语义、授权和保留策略；字段/表/周期参数必须由真实合同决定。

本ADR仅接受上表明确的新云图独立同步/阅读、来源数据分层与产品入口边界；02的核查/报告材料和处置状态扩展仍为提议。字段、表、周期参数及材料保留策略必须依01A合同与后续批准切片确定。不代表01A真实验证已通过，不批准真实云图/模型调用、扫描/写回、业务实施或部署；本轮文档远端发布按#245的明确授权执行。

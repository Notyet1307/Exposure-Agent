# ADR-0022：有界资产批次可读，不冒充完整版本

状态：已接受（2026-09-25）。维护者已明确批准“少量数据先在正式页面可用”的有界批次合同，授权本次规格按正常CI/Review发布、固定及建立实施任务；本文随修订Spec固定后由该任务实施，不自动授权业务代码远端合并、生产部署或新增真实调用。

#253实读已证明IP与端口基本字段及单例同IP匹配可得，但来源连接中断使完整遍历之前取得的合法数据始终无法进入正式页面。新手动采集改为两域公平分配页额度、逐页轮转；每域正常到达自己的批次额度即可封存并独立发布，显式区分本批条数与来源报告total。只有确已读完请求范围才标记完整；未知、异常、撤权和指纹漂移不构成封存理由。

这是对ADR-0021“最近完整结果”阅读策略的窄扩展：默认入口可读最新正常封存批次，另保留最近仍可读完整版本入口；失败不清空旧完整结果，部分批次不覆盖历史内容。继续沿用PostgreSQL、agent-compose、OctoBus、项目/来源权限、保留期限和固定版本身份，不引入临时预览页、跨批次合并、第二调度器或源调用重试。

放弃“全部读完才允许看到任何数据”，因为它把完整性核验与可用性绑在一起；也不采用“任何失败暂存都能展示”，因为它绕过页完整性、授权复核及Session未知保护。代价是必须保存可信的正常封存依据，并在任务、版本、列表、详情、同IP匹配及最近完整版本入口中持续呈现非全量范围。

精确行为和验收见[Spec的2026-09-25修订及ACBATCH-1—5](../specs/exposure-focus-release-1.md)。旧任务按创建时合同执行，同键恢复不重调度；#250及#253历史结果不追溯升级。旧Run/报告、共享迁移、风险及其他资产域的边界不变。

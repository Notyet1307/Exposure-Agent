# ADR-0023：新处理结果的默认保留期与历史兼容

状态：提议，待维护者批准并由实施 Issue 固定同版 Spec。

依据：2026-10-04 维护者确认三源数据独立查询、客户最新版持续维护、云图与 NetFlow 处理后数据默认保留 90 天且可配置，并选择 A 方案在现有前端落地。精确条款与验收见 [三源比对工作台 V1](../specs/three-source-workbench-v1.md)。

## 问题和已有约束

云图已有逐批绝对截止及到期拒读/窄 purge；NetFlow 新处理链尚无相应结果期限。把前端的“90天”标签视为已实施，会让显示与真实读取不一致。直接对旧 Dataset、原始文件和旧 Run/报告追加自动 TTL，又会改变历史输入与引用边界。

ADR-0009 当前文本是“提议”，其中无 TTL/自动清理条款不能误报为已接受 ADR 冲突；它描述的原始/规范化 Dataset 归档边界仍不在本次扩展范围。继承已接受 ADR-0008/0016/0018/0020/0021/0022 的固定身份、输入、权限与兼容约束。

## 决定提案

1. 项目默认保留天数是新批次配置，不是修改既有内容的权限。默认 90，配置受管理权限、版本并发控制和审计约束。
2. 云图继续固定本次明确的 `retain_until`；项目默认只提供新同步的初值。本次操作仍明确授权来源、范围、预算和截止，不因设置默认而自动访问来源。
3. 新 NetFlow Analysis 固定预留时的保留策略，并在首次成功发布时固定结果截止。其观测/peer/复核/反馈结果及受控结果证据继承同一生命周期；追加反馈或读回不续期，策略变化不创造新的处理身份或重复任务。
4. 原始 NetFlowDataset 及其 raw/normalized Artifact、客户清单与旧治理事实保持原合同。处理结果到期不会改写它们，界面也不得借这些资料假装恢复原 Analysis 的结果。
5. 不回填旧版本期限，不复活已过期版本。旧 Analysis 期限未记录时如实显示历史规则，不宣称其已受 90 天约束。
6. 期限首先是读取边界：全部新结果读取面与前端缓存一致拒读到期明细；保留非敏感元信息墓碑。独立来源不因另一个来源到期而一并删除或伪空。
7. 不增加清理调度器。到期物理清理由 Admin 明确操作，限于可证明归属且无受保护外部引用的处理产物；元数据、原始输入、旧 Run/报告及备份不作为该操作的删除目标。有关联的新结果可通过到期墓碑表达不可读，不复制明细绕过保留。

## 取舍

拒绝在每次 GET 重新计算“今天起90天”，因为这会让数据永不到期；拒绝只修改前端文案，因为 API 和缓存可绕过；拒绝全仓库回填 TTL，因为会改变旧资料可读性；拒绝复制关联明细来延长保留，因为形成第二套事实与授权边界。

代价是增加项目默认策略、逐处理批次期限与明确的到期读取/清理状态。换来可解释的前后端一致行为，同时保留原始输入和历史治理合同。不是对全部原始资料或备份作“90天后自动销毁”的承诺。

## 接受与验收边界

批准本 ADR 和同版 Spec 后，新任务才能实现该窄扩展；不据此修改当前真实空间旧截止、生产数据或旧任务状态。验证须覆盖完整结果读取链、引用保护、历史兼容和清理失败；仅字段/界面检查不足以证明留存生效。

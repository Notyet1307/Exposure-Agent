# 主流程演示与恢复

本说明面向现有单实例产品的操作演示。行为以批准 [Spec](../specs/asset-governance-release-1.md) 为准；任务状态、当前候选与验收结论查对应 GitHub Issue。本说明本身不是通过回执。

## 演示准备

使用已明确获准的合成材料及隔离环境。管理员可创建项目和管理部署级模型连接；项目 Operator 可提交治理与 AI 任务，Viewer 只读。不要在客户环境中用演示脚本更改来源或模型，不将客户数据作为合成材料发送。

## 连续操作

1. **新建比对项目**：填写项目名称，提交后进入该项目的准备页。若响应未知，使用“恢复创建请求”，不要换名称重复创建。
2. **准备三类输入**：接受并选择 XLSX 台账；绑定、验证、启用既有 CloudAtlas 来源；按需要选择或跳过 NetFlow。已接受、当前选择和本轮固定版本是不同事实。输入被拒绝时修正原文件，不必重建项目。
3. **确认并开始**：进入输入确认，核对版本并明确提交。等待真实发布成功后进入固定 Run 概览。NetFlow 未提供时显示不适用；零记录与 UNKNOWN 均不表示零风险。
4. **查看 AI 状态**：首页 AI 工作区展示当前连接就绪情况。管理入口属于全局管理员；保存待启用版本、合成验证、启用各是独立动作。连接 ready 不代表项目材料获准，打开设置不会启用模型。
5. **核查单个资产**：从本轮资产列表选定资产，核对项目、Run 与 IP。显式提交 AI 核查后阅读事实、解释、缺口、下一步，以及实际工具读取时间与引用。快捷问题仅填入问题，仍需明确提交。
6. **保存人工记录**：自行填写结论与待验证事项。人工记录不关闭 Finding；修正追加新版本，保留旧记录。
7. **形成报告**：通过“本轮报告”回到同一个 Run，显式生成草稿，选择对应版本。AI 原稿、人工编辑和最终确认分别保存；先保存编辑再确认。材料变化需要新草稿，历史确认版不被覆盖。
8. **回读历史**：切换已发布 Run 后核对上下文，刷新仍保持所选 Run。当前模型与历史任务连接版本分开；旧 legacy 记录不归属后来启用的模型。

## 异常与恢复

| 状态 | 可执行下一步 | 验收时应确认 |
|---|---|---|
| 无权限或权限被撤销 | 联系管理员核对角色，以 Viewer 阅读已授权事实 | 不显示或提交越权写操作，不继续显示被拒绝范围的缓存 |
| 台账格式错误 | 修正必需结构后重新上传 | 保留现有选择，拒绝不伪装成功 |
| 来源验证失败或禁用 | 检查来源绑定与部署凭据，重新验证后显式启用 | 未就绪时不能开始；其他已接受输入保留 |
| 请求结果未知 | 查询或恢复原操作/幂等 key | 刷新不是另起任务，不用新 key 隐藏未知结果 |
| Run 失败 | 阅读失败原因，按服务端允许的 Retry/Rerun 修复 | 原失败 Run 保留，Retry 与新 Run 分别识别 |
| 模型未配置/验证失败/不可用 | 管理员检查连接；事实、历史、人工记录仍可读 | 不自动切换版本，不把固定响应测试当真实模型语义 |
| 报告编辑冲突或材料变化 | 保留编辑，读取当前版本；新材料创建新草稿 | 原稿和确认版保持，人工确认单独执行 |

## 可重复验证入口

`frontend/tests/first-comparison.spec.ts` 覆盖真实隔离环境的创建、输入拒绝、来源准备、首轮发布及有/无/零记录 NetFlow；`tests/model_connection_backend/workflow-browser.mjs` 覆盖固定 Run 的核查至报告流程。组合链路与运行参数以仓库当前测试脚本为准，禁止把预置发布事实的短测试作为真实首轮发布证据。

组件测试用于权限、弱网/晚响应、历史范围、三宽度和界面反馈。固定 Provider 只能证明调用、材料与状态合同；外部模型语义、客户生产环境、用户亲自确认须分别记录。截图说明布局，连续请求/操作记录说明动态行为，两者不可互换。

交付记录应列明候选 SHA、批准 Spec、样例/环境、逐 AC 的 PASS/FAIL/BLOCKED/NOT_RUN、初次失败与后续重跑、已知限制和部署范围。真实客户材料、Secret、固定 Run 快照与临时日志不提交进仓库。

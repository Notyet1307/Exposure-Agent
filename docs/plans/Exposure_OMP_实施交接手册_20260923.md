## 1. 已确认的产品方向

### 1.1 一句话定位

Exposure 是能够独立使用、也能被其他智能体调用的外部暴露核查与处置产品。它利用云图发现结果、客户既有管理信息和网络活动线索，回答：哪些外部暴露值得处理、为什么、应如何处理、处理后是否达到验证条件。

### 1.2 本轮新增的硬要求

云图已有的资产信息与风险信息必须同步到 Exposure 本地。用户应当能够在 Exposure 完成已约定范围内的资产查看、风险查看、依据阅读和相关核查，不需要跳到云图完成这些阅读动作。

这不是只同步 IP 列表，也不是展示几个风险数量，更不是用 iframe、外链或实时透传详情冒充本地同步。外链可以作为可选诊断入口，不能是完成核心任务的必经步骤。

完整性以“客户实际云图版本、授权空间、接口或正式导出能力、约定信息清单”作为可验证边界。接口不能提供的内容必须显式列为缺口，不能擅自删掉需求再宣称完整同步。未知接口、字段、权限与分页语义不得编造。

### 1.3 保持不变的边界

- 外部资产和相关风险在 Exposure 中完整阅读；本地只维护核查、关注、处置等业务信息，不复制云图的扫描引擎和全部后台管理功能。
- 内部资产仍由客户原平台维护。Exposure 只读取核查所需的归属、业务、责任人、报备及审批信息，不扩建内部资产 CRUD 和生命周期管理。Excel 是兼容输入，不是新的主数据平台。
- NetFlow 是暴露线索提取能力，不是独立的完整资产管理产品。NetFlow 独有对象先作为待核查候选，不能未经确认就进入正式外部资产目录。
- Laya 是拟采用的本地分类能力，需核对实际项目、版本、许可与场景效果。模型替换不阻塞规则版 NetFlow 能力，不默认开启训练项目。
- 去掉面向普通用户的独立血缘入口，保留有用的来源依据和历史关联。删除可视化不等于删除完整性保护或历史事实。
- 审计围绕“一个暴露问题/一次专业任务”的业务时间线组织。完整 Hash、内部 ID、运行版本等进入受控技术详情，不散落在主列表和业务摘要中。
- Exposure 保留自己的 Web 工作台，并把专业能力输出给 cumora。两边复用同一业务服务和权限约束，不共享可任意写入的数据库，不重复维护资产和问题状态。

### 1.4 第一项可演示成果

一个没有内部台账、没有 NetFlow 输入的新项目，在配置了被授权的云图来源后，可以独立同步云图资产及风险，浏览资产详情、风险详情和约定范围内的依据。同步完成后暂时断开云图连接，已有本地内容仍可查看，并正确显示数据时间与更新失败状态。

这是第一个业务里程碑。不要先花大量工作做首页样式、Laya 替换或 cumora 对话，而云图仍然只有 IP 和状态。

## 3. 产品模型和数据责任：只保留必要的区分

以下是领域含义，不要求直接建立同名数据库表。OMP 应优先复用现有模型，再提出最小变更。

| 对象 | 回答的问题 | 责任边界 |
|---|---|---|
| 外部资产/服务 | 云图发现了什么对象、什么服务，其属性是什么 | 上游值保留来源和更新时间；本地数据用于独立阅读和核查 |
| 云图原始风险 | 云图对哪个对象报告了什么风险、等级、依据与状态 | 原判断、原等级和原状态不得被本地 AI 或处置状态覆盖 |
| 暴露问题 | 本地需要谁处理什么，当前推进到哪里 | Exposure 保存核查结论、责任确认、动作、复测和关闭依据 |
| 核查/同步/动作任务 | 这次工作做了什么、成功到哪里、失败在哪里 | 有明确范围与终态；失败、取消和结果未知不冒充成功 |

一个原始风险不必机械地对应一个暴露问题；多个有关风险是否合并，应由明确规则或人工确认决定。本阶段先保证稳定关联，避免为了去重而误合并。

源风险状态与本地问题状态可以并列显示。例如“云图状态：仍存在；本地进度：业务反馈已处理，待复测”。不因工单反馈完成就关闭，不因下一次同步没看到记录就认定修复。

PostgreSQL 仍是 Exposure 本地结构化业务事实的权威存储；云图源字段的判断来源仍是云图。本地备注、优先级、处置进度单独保存，不修改来源字段来伪造上游变化。

Web、cumora 和 Exposure 内部 AI 应调用同一套业务服务；浏览本地详情不触发云图、扫描或模型任务。模型输出只能补充解释和草稿，不能创造上游事实或批准动作。

## 4. 云图同步：必须先定义“完整”，再实现

### 4.1 覆盖清单

下面是待确认的信息类别，不是已经核实的云图接口字段表。OMP 必须依据现有接口资料、脱敏响应和实际授权空间逐项填入：实际接口/导出来源、字段路径、稳定键、是否可得、本地保存方式、页面位置、验收方式与缺口。

| 类别 | 需要核对的信息 | 本地体验要求 |
|---|---|---|
| 资产身份与归属 | 资产类型、来源 ID、来源空间、IP/域名/URL 等实际支持的标识、归属信息 | 可搜索并进入同一对象的详情；不能仅凭相同 IP 跨来源空间合并 |
| 资产详情 | 实际提供的端口/服务、组件、指纹、证书、网站、标签及其他有业务价值的属性 | 不只保存列表摘要；提供结构化展示，不把大段原始 JSON 作为主要交付 |
| 资产时间与状态 | 发现时间、更新时间、观测时间、上游状态及其定义 | 明确原始状态语义，不能从 status 猜风险或监控状态 |
| 风险清单 | 稳定风险标识、名称、类别、等级、受影响对象、上游状态与时间 | 有完整列表、筛选、分页及风险到资产的可靠关联 |
| 风险详情 | 描述、检测依据、影响说明、修复建议、已有历史等实际可得内容 | 页面内可读完整约定详情，不能只有标题、等级和外链 |
| 依据与附件 | 实际存在的截图、请求响应、附件、证据文本等 | 约定范围内可本地阅读；敏感信息受控；过期外链不能算完成同步 |
| 关联与历史 | 风险指向资产/服务的关系、上游可提供的变化记录 | 关联暂不完整时保留风险并显示待关联，不能悄悄丢弃 |

每行的处理结果只能是：已验证可同步、待核实、接口缺失、权限缺失、明确不适用。缺失项必须保留在交付差距清单。未经用户明确缩小范围，不得把必需字段改成“以后再说”并宣布完成。

### 4.2 同步行为

初次完整读取之后，支持按确认策略更新。上游有可靠增量接口时使用增量；没有时采用有界全量校对。不要虚构 webhook、增量游标、删除通知或稳定快照能力。

同步频率、并发、限流、数据量和附件保留空间应通过合同和测试确定，不先许诺固定秒级实时性。可以先交付手动同步子切片，但该子切片不能冒充最终的持续更新能力。

一次分页失败、超时或权限错误，不应清空上次成功数据。应保留最近完整结果，另行展示本次失败或局部更新边界。资产与风险可以分域更新，但读取必须显示各自时间，不能把不同时刻的数据宣称为一个原子快照。

分页期间发生上游变化时，按实际 API 能力处理稳定排序、去重和补读；无上游快照语义就不宣称强一致。总数对账必须使用可比较的过滤条件、范围和时间口径。

同步重复执行不产生重复资产、风险或业务事项；按经验证的稳定来源身份进行幂等处理。源 ID 长期稳定性未证实前，不靠猜测强行跨批次继承。

增量未返回某条记录不等于删除；完整读取中记录消失，也需要核对权限、过滤、状态范围与上游删除语义。默认保留历史和明确的“上游未再观测/待确认”状态，不自动关闭本地问题。

同步和浏览必须独立于内部台账、NetFlow 与旧对账 Run。用户不需要先新建比对项目或选择 Run 才能看云图资产。

### 4.3 安全与数据边界

真实云图凭据、原始资产 IP、请求响应和未脱敏风险证据，不进入公共 Git、GitHub Issue、模型上下文或审阅材料。先核对既有私有存放位置与材料，不搜索/打印密钥值。

新增风险接口与附件读取需要明确的只读授权范围；旧的 IP 列表授权不能自动扩展为所有云图权限。附件抓取只使用确认来源和受控网络边界，限制类型、大小与重定向，不允许由上游字符串任意访问内网地址。外来 HTML/文本安全展示，不把它们当作可执行脚本或智能体指令。

本地 API、页面、导出和 cumora 调用都执行当前 Project/SourceInstance/用户范围授权，不能因为数据已经同步下来就扩大可见范围。明确撤销连接、撤销成员权限后本地数据的可见性与保留策略。

### 4.4 关键验收

在确认的覆盖清单内：资产和风险数量与来源范围相符，详情和依据完整，本地可搜索可关联可阅读，失败不清空、重复不新增、权限不越界、旧报告不受影响。暂停 Exposure 到云图的连接后，已同步范围仍可读；界面明确显示最后成功同步时间和当前更新状态。

没有真实接口验证时，只能称“合成合同验证完成”；不能把 fixture、HTTP 200 或编译通过当成完整云图同步验收。

## 5. 分阶段路线：目标先入仓库，再变成 Issue

这些阶段按用户结果组织，不按数据库、接口、前端三层分离交付。后续阶段只保留范围与验收方向，不提前过度设计全部技术细节。

### EXP-FOCUS-00：产品收敛接管与规格定稿

背景：旧路线围绕三账管理和 IP 对账，新路线需要完整云图本地阅读与问题闭环，存在已接受 ADR 冲突。

目标：核对当前实现，确定复用、收敛和必要变更，让新会话无需聊天历史也知道做什么。

输入：本文件、AGENTS.md、current.md、当前 Spec/Issue、相关 ADR、代码和测试；已存在的接口资料及脱敏样例。

范围：只读核对业务代码；允许新增接管回执、候选计划、字段矩阵、必要 Spec/ADR 草稿和 Issue 候选正文。检查当前 OMP 版本、可用 Skills 和真实验证入口，不自动升级。

非目标：业务源码、数据库迁移、自动建单、提交/推送、生产调用、真实扫描、部署。

产出：能力差异清单；旧新条款冲突清单；完整同步字段矩阵初版；阶段定义与候选依赖；第一项候选 Issue；后续所需材料和授权。

完成标准：旧功能不重复立项；新方向和未知项分开；第一项可执行工作明确；第一阶段未被缩成 IP 列表；没有破坏现场或原工作树。

停止条件：交接文档与候选规格完成即停止。关键接口缺失时列出最小缺口，仅阻塞依赖该接口的实施，不妨碍完成接管和其余确定部分。

### EXP-FOCUS-01：云图资产与风险本地工作台

背景：客户不希望为查看完整资产与风险反复进入云图，而当前合同只包含 IP 列表摘要。

目标：实现独立同步和本地阅读，成为之后核查与处置的可靠输入。

依赖：00 完成，所涉新 Spec/ADR 已获批准；真实接口核验具有明确的只读授权。

建议拆成三个顺序候选任务；正式 Issue 编号由 OMP 建单后映射：

- **01A 接口合同与权限核验**：完成字段矩阵、列表与详情接口、风险关联、分页/更新时间/删除语义、附件来源、数据量与失败分支核验。必要时用隔离试验验证。真实读取和合成验证分别记录。
- **01B 第一条资产—风险纵向链路**：选择已确认的一类对象，经过 OctoBus 读取、落地、本地查询、详情和关联展示贯通。不扩展内部台账，不依赖 NetFlow。提供可真实演示的最小路径。
- **01C 补齐覆盖与可靠同步**：补齐已确认资产/风险类别、详情和依据；完成手动/周期更新、幂等、错误保持、权限、离线读取、历史兼容和页面收敛。按完整矩阵验收，而不是拿 01B 代替阶段完成。

主要界面：工作台、外部资产（包含风险清单/详情）、核查与处置、报告；接入和任务诊断进入设置。若风险需要独立常用入口，可作为外部资产内的明确视图，不因此创建一套新产品。

非目标：复制云图扫描引擎、建设通用 CMDB、外部写入/纳管、自动渗透、全量重写旧报告。

完成标准：见第 4 节关键验收；无需内部台账与 NetFlow 即可完成本地阅读；旧客户台账/NetFlow 台账/血缘不再是普通客户主导航。历史链接通过受控历史入口或兼容路由保留，不大删数据库。

停止条件：当前正式 Issue 完成后固定候选，等待独立验收与对应交付授权；不得自动进入 02。

### EXP-FOCUS-02：一条暴露问题的核查与处置闭环

背景：完整数据可读仍不等于完成安全工作，需要把需要处理的风险转成明确事项。

目标：选一个已同步的外部资产/服务或风险，从提出问题、核查、人工确认、交办到复测完成闭环。

输入：01 的本地资产与风险事实，现有 AI 核查/人工记录/报告能力，明确的问题类型与关闭条件。

范围：源风险与本地事项分离；复用现有核查能力；本地责任/待办/外部工单引用；任务统一时间线；复测依据；AI 不可用时可手工完成关键流程。

首个场景优先选择已有核查工具能够验证的问题，不为了演示新造扫描器。对外真实扫描或写接口仅在另行批准范围内执行；没有执行器时可形成待执行计划和人工回执，不能冒称自动完成。

非目标：通用工单平台、全自动封禁/关停、任意 Agent 编排、重写所有 Finding 历史。

完成标准：一个普通用户无需理解 Hash、Artifact 或 Run 即可完成问题处理；源风险等级/状态保留；“已交办”“反馈已处理”“复测通过”明确区分；复测失败和证据不足不关闭；失效数据不能支持当前肯定结论。

依赖和停止：依赖 01；当前切片验收后停止，待批准进入下一项。因复用旧模型产生状态冲突时先完善必要规格，不静默改历史语义。

### EXP-FOCUS-03：NetFlow 暴露线索提取与 Laya 资格验证

背景：全量流量端点不应再次变成独立资产账，价值在于筛出值得核查的新增/漏管外部服务。

目标：把既有 NetFlow 处理能力转成“输入数据 → 提取线索 → 解释原因 → 发起核查”。

输入：已有 NetFlow 数据集/授权网络范围/时间与采样上下文，01/02 的外部资产和核查路径，实际 Laya 项目与版本材料。

范围：先确定性过滤与聚合，再对模糊服务角色进行可替换分类。NetFlow 独有对象进入候选队列；受管范围外 peer、未知归属和客户端通信不能自动进入正式外部资产。保留有活动、疑似服务、外部已验证的区别。

实施顺序：先完成规则基线与可演示工作流，再离线比较规则版与规则＋Laya。核对本地部署条件、许可证、语言/字段格式、置信度校准、错误分布与资源消耗；默认不做训练工程。

非目标：通用 NDR/SIEM、全流量存储平台、默认识别所有攻击、不经授权向云图写入候选。

完成标准：给出有限且有依据的候选；漏检/误报/不确定项有评测；Laya 失败或不通过仍可使用规则与人工；既有 NetFlow 记录数语义和历史报告不变；空记录、无输入、无观测不能当成零风险。

依赖和停止：依赖 01/02 的消费者；模型效果不足只阻止模型默认启用，不阻止规则版交付。

### EXP-FOCUS-04：cumora 调用 Exposure 专业能力

背景：用户希望 Exposure 不只是一个独立网页，也能被统一协作入口调用。

目标：同一份业务事实、同一项核查能力，能够从 Web 和 cumora 发起/读取，并保持权限与状态一致。

输入：Exposure 的固定业务 API/权限合同，cumora 当时的代码、信任配置与支持协议。不要依赖本文件读取时的 README 推定以后部署状态。

范围：先少量只读能力（资产/风险上下文、待核查问题、最近变化），再提供提交核查任务、查询状态、获取成果。优先选择现有接入路径中的最小适配，不同时新建 MCP 与 A2A 两套重复执行链。

建议能力名只表达接口意图，不声称已存在：`get_external_asset_context`、`list_exposure_cases`、`submit_investigation`、`get_investigation_result`。实际命名、Schema 与分页由批准 Spec 决定。

运行边界：Exposure 是资产/风险/问题和任务状态的权威；cumora 是对话、协作和成果采用入口。长任务返回任务身份和明确进度，不只有大段文本。服务端从凭据映射权限，不接受模型传入任意 Project 作为授权。取消、撤销与未知远端结果各自定义，不因超时用新请求盲重试。

非目标：共享数据库、重复建资产主表、绕过 cumora 信任限制、任意 URL 或任意 SQL 工具、把“采用报告”视为执行批准。

完成标准：通过 cumora 真正完成一次只读业务查询和一次核查任务；结果指向 Exposure 中同一事项；越权、禁用、重复提交、未知状态都验证。跨容器/异机不能用放宽到任意地址来解决连接问题。外部写入/扫描能力不随本阶段自动授权。

依赖和停止：读取合同设计可早做，但正式实现按单任务推进；涉及两个仓库时分别绑定 Issue、Spec、候选版本与权限，不允许一个仓库自动改另一个仓库。

### EXP-FOCUS-05：一体化验收与交付

背景：各切片分别完成不等于整体可用，也不等于实际环境已经升级。

目标：以真实业务链、隔离故障测试与明确的发布边界，确认本轮可以交付。

范围：云图完整本地阅读 → 建立问题 → 核查与交办 → 复测 → 时间线与报告 → cumora 查询/任务；验证 NetFlow 规则基线及 Laya 实际启用状态；检查主导航、历史兼容、权限、恢复、数据新鲜度和缺口。

非目标：验收时顺手增加功能、修改合格条件以消除失败、用重新造数据覆盖真实失败。

完成标准：按固定代码和 Spec 版本逐项给出 PASS/FAIL/BLOCKED/NOT_RUN；部署与代码完成分开记录；保留回退方案，确认数据迁移不可被旧程序错误解释；在授权环境做验证，真实客户数据不进入公共证据。

停止条件：存在阻断项则不宣称交付完成；列明已完成范围、未完成范围与唯一下一动作。

## 6. 仓库落点与 OMP 使用纪律

### 6.1 最少的正式材料

本文件保存产品方向和阶段定义。新行为需要在仓库约定的 Spec 中正式定义：可选择一个新的聚焦规格（例如 `docs/specs/exposure-focus-release-1.md`），或使用仓库认可的现有规格扩展方式。具体落点在 00 核对，避免并存两份内容不一致的权威规格。

发生已接受 ADR 冲突时新增必要 ADR，说明替代了哪些条款以及适用边界；编号按仓库实际序列生成，禁止猜测已有编号。历史文件不整篇推翻，旧报告和 Run 的固定合同继续有效。

`docs/work/current.md` 只放当前任务、固定 Spec、候选/证据入口和停止线，不复制长期任务状态表。正式任务状态、授权和依赖只在 Issue。

每个切片在仓库已有位置保存脱敏交接/验收回执。新会话只读 AGENTS.md → current.md → 固定 Spec/Issue → 相关代码，即能恢复工作。不要要求用户重新讲“第二阶段是什么”。

### 6.2 OMP 和 Matt Skills 的分工

OMP 原生能力负责代码阅读、修改、测试和审阅；GitHub 原生能力负责 Issue、PR、CI 和交付记录。按仓库当前规则采用单写者；可并行做只读探查与审阅，但不要多个 Agent 同时改同一候选。

Matt Skills 按实际安装情况辅助需求审问、规格和任务拆分。先检查真实技能清单；没有某 Skill 时按照方法做，不猜命令、不为本轮自动安装新 Harness，也不恢复历史 Controller。

OMP 官方当前文档列有 `/review`，但本地版本和实际可用能力仍需核验。原生 reviewer 分别核对仓库 Standards 和批准 Spec；独立业务验收另开干净上下文，不把代码审阅当成浏览器业务验收。

已经授权的单个 Issue 内，允许完成正常实现、失败定位、修复和必要复测，不为每个文件编辑或常规测试反复要授权。新功能范围、真实环境、新来源读取权限、远端发布和部署不被自动推导为已批准。

### 6.3 验证入口

下列命令来自本次读取的 AGENTS.md，执行前仍需核对当前分支与隔离环境：

```bash
python3 scripts/check-context-hygiene.py
cd backend && uv run bash scripts/lint.sh
cd backend && uv run bash scripts/tests-start.sh
cd frontend && bun run lint
cd frontend && bun run build
```

每条带 `cd` 的命令均以仓库根目录为起点，不能直接在同一 shell 连续粘贴而忽略当前目录。API 合同变化时按仓库脚本生成客户端，不手工改生成文件。完整后端测试需要 PostgreSQL；缺少环境必须报告 NOT_RUN，不以命令未执行代替通过。

cumora 集成测试可能清空数据库，必须使用明确可销毁的隔离测试库；不能把未配置环境导致的 skipped/退出码 0 算作集成通过。

## 7. 接管时先找什么材料，缺什么才补什么

先搜索仓库现有的云图接口文档、来源配置说明、脱敏响应、测试 fixture 和既有集成回执；不要让用户重复提供已经存在的材料。

| 材料 | 最小需要内容 | 不允许的替代方式 |
|---|---|---|
| 实际资产接口 | 列表、详情、类型、分页、稳定标识、状态与时间语义 | 根据产品截图猜 endpoint/字段 |
| 实际风险接口 | 列表、详情、受影响对象、依据、状态、分页、历史能力 | 用资产 status 或风险数量推导完整风险信息 |
| 页面覆盖样本 | 代表性资产页与风险详情页对应的脱敏数据 | 只看列表就断言所有详情都能同步 |
| 来源范围与只读权限 | 哪个环境、哪个空间、允许哪些读取接口、调用限制 | 复用旧 IP 列表权限默认读取所有数据 |
| 规模与运行要求 | 大致资产/风险数量、附件规模、更新时间要求 | 任意承诺秒级实时或无限存储 |
| Laya 材料 | 用户实际指向的仓库/模型、版本和本地方式 | 按同名项目猜支持能力 |
| cumora 接入环境 | 当前版本、可用协议、网络位置和批准信任范围 | 保存一条连接即宣称端到端打通 |

真实凭据只保存在既有受控私有路径或秘密管理机制中。公开仓库只接收脱敏合同、合成测试材料和聚合验收结果。

## 8. 核心验收矩阵

以下全部是待执行标准，不表示已经通过。每个正式 Issue 应从中选取直接相关项并补充明确数据、步骤和预期，不把整张表机械复制为每项任务的门禁。

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 无内部台账、无 NetFlow | 云图同步和本地资产/风险阅读独立可用 |
| A02 | 超过一页的资产与风险 | 遍历真实合同分页，数量/范围可核对，无截断或重复 |
| A03 | 资产和风险详情 | 已确认矩阵的字段、关联、依据可结构化阅读，不只标题或原始 JSON |
| A04 | 断开云图连接 | 已同步详情与约定附件仍可读，显示数据时间和更新失败，不伪装在线新鲜 |
| A05 | 第 N 页失败/鉴权失效 | 不清空上一完整结果，不把部分采集记为全量成功 |
| A06 | 重复同步/重试 | 不重复创建来源对象、风险和事项；未知写入/外部执行不盲重试 |
| A07 | 风险先于资产到达 | 风险保留并标明待关联，不丢失、不错误绑定其他空间相同 IP |
| A08 | 记录从某次结果消失 | 不自动推导已修复或关闭，核对过滤/权限/删除语义 |
| A09 | 各数据域更新不同步 | 分别展示更新时间/范围，不虚构跨域同一快照 |
| A10 | 来源/用户权限撤销 | 页面、直调 API、导出和 cumora 一致受限，日志不泄漏秘密 |
| A11 | 同步任务重启/中断 | 有可解释状态与安全恢复路径，不重复执行、不依赖网页一直打开 |
| A12 | 旧历史回归 | 既有 Run、报告、引用、共享迁移和模型配置不被改写 |
| A13 | 主界面收敛 | 三账和血缘不再占普通用户主导航；核心页面无散落完整 Hash |
| A14 | 人工核查与 AI 故障 | AI 不可用时仍可记录结论、待办与有效依据，不能造源事实 |
| A15 | 源风险与本地处置 | 源等级/状态与本地优先级/进度分离，不互相覆盖 |
| A16 | 业务反馈完成但复测失败 | 问题保持待处理/待复测，有明确失败与后续动作 |
| A17 | NetFlow 候选 | 受管范围外 peer 不纳入；有活动不等于已验证暴露；未知保留 |
| A18 | Laya 资格验证 | 相对规则基线的错误与收益有证据，未通过不默认启用 |
| A19 | cumora 实际业务调用 | 权限内查询和核查任务真实完成，业务状态与 Exposure 一致 |
| A20 | cumora 超时/禁用/重放 | 结果未知不当成功，禁用阻止新调用，重放不另开重复任务 |
| A21 | 覆盖缺失 | 不支持字段/附件与真实验证未覆盖项明确列出，不把“部分完成”改名“完整同步” |
| A22 | 真实资料保护 | Git、Issue、公开日志、云端模型和审阅上下文中无未批准的客户数据/凭据 |

### 8.1 业务演示必须分开三件事

代码构建成功，是构建验证；测试通过，是对应测试环境的验证；真实云图只读连接验证，是指定来源的集成证据。三者不能相互替代。模拟扫描器或模拟工单用于测试时必须标明模拟，不得对客户宣称真实执行。

### 8.2 什么叫“该阶段可以结束”

目标内的必需验收通过；未完成和不适用项有明确边界；Spec/代码候选绑定；独立审阅和业务验收分别完成；部署是否属于当前任务已经明确；交接回执能指导下一会话继续。不是“已经写了很多代码”或“所有已运行测试都通过”。

## P1：批准文档基线并建立第一项正式 Issue

```text
我认可本轮接管回执，批准其中明确列出的产品收敛决定，以及 EXP-FOCUS-01A“云图资产与风险接口合同核验”的规格。
尚未核实的 API 字段、权限、模型效果和部署事实仍保留为未知，不能因这次批准而标记已验证；未列入批准范围的后续实现仍是候选。

授权你完成这批文档的本地提交、push、文档 PR、必需 CI/Review，并在满足仓库规则后合并；如果仓库当前流程要求计划任务也有 Issue，可先建立仅覆盖本次文档定稿的明确任务。禁止绕过分支保护或强推。

文档基线固定后，查重并创建 EXP-FOCUS-01A 的正式 Issue，引用批准 Spec 的准确路径与 commit，明确 AC、依赖、验证方法、资料缺口、真实只读调用的权限边界和停止条件。
其他阶段保持候选，不批量创建一堆未定规格的实现 Issue，不开启业务源码开发。

必要的新 ADR 只替代被明确批准的旧条款，保留旧 Run/报告合同；同步更新默认文档阅读入口，使 OMP 能找到新规格。docs/work/current.md 只作为任务/规格指针，任务状态仍以 Issue 为准。

本轮不授权真实云图/业务模型调用、扫描、纳管、写回或部署，不授权业务代码修改。未得到真实来源授权时，01A 的验证计划必须明确哪些只能用脱敏文档和合成样例核验。

完成后返回文档版本、PR/Issue、准确的下一步实现提示词和仍需提供的最小材料，随后停止。
```

## P2：实现一个已批准的正式任务

```text
执行 Exposure 的正式 Issue #[ISSUE_NUMBER]，只实现该 Issue 固定 Spec 的范围。

先读 AGENTS.md、docs/work/current.md、该 Issue、固定 Spec、相关 ADR 和最小必要代码/测试。确认任务未被其他 PR/工作树实现；发现状态不一致先核对，不重复做。

本轮授权：在隔离分支/工作树内完成本 Issue 的代码、必要的新增迁移、生成客户端、测试、必要修复、文档回执和本地提交。正常的范围内编辑与复测不需要逐文件询问。
本轮不授权业务代码 push/PR/merge、部署、修改生产数据、未明确批准的真实云图/业务模型调用、扫描/纳管/写回，也不自动推进下一 Issue。01A 等需要真实只读验证的任务，只能使用已有且适用于本轮的明确授权，不能从旧权限推导。

先给出最小实现路径，优先复用已存在的来源、核查、调度和审计能力；不要新建通用平台或恢复历史 Controller。云图能力要保留完整资产/风险信息目标，不能以 IP 摘要代替。

采用单写者。可并行做只读分析与审阅；按需使用实际安装的 Skills。实现后使用 OMP 原生 reviewer 分别检查仓库 Standards 与批准 Spec。修复本 Issue 内的 blocker 并重新审阅；业务独立验收另行记录，不用代码审阅代替。

测试必须使用隔离环境。分别报告 PASS/FAIL/BLOCKED/NOT_RUN；假接口与真实接口验证分开；不改验收条件来消除失败。不覆盖共享迁移、历史报告、原始 Run、模型配置或其他工作树。

完成后固定候选代码版本，输出：用户现在能做什么、未完成什么、测试和审阅结果、复用/修改范围、历史与权限回归、候选版本、脱敏证据入口和独立验收方法。
随后停止，不自行发布或进入下一阶段。
```

### P2-R：需要真实云图只读核验时的附加授权

这段仅在指定环境、来源空间、只读接口清单和调用限制已经写进当前批准任务后发送。它补充 P2，不授权任何写入或扫描。

```text
针对当前正式 Issue #[ISSUE_NUMBER]，另外授权使用该 Issue 已明确的云图环境、来源空间、只读接口清单与调用限制，完成本阶段真实只读集成核验。

只使用现有受控私有配置中的凭据，不打印秘密、不把原始客户资产/风险/响应送入模型、Git 或 GitHub。允许发布脱敏合同、合成复现材料和聚合结果。
不得扩展到清单外接口、其他租户/空间、扫描、纳管、风险处理写回或部署。旧接口权限不能替代本次清单的权限。
如果任务尚未明确环境、接口范围或安全的凭据使用方式，只停止真实调用这一部分，列出准确缺口；不得自行猜测目标或扩大权限。真实验证和故障合成测试分别记录。
```

## P3：新会话独立业务验收

```text
你是本候选的独立业务验收者，不是实现者。
验收 Issue #[ISSUE_NUMBER]，候选代码 [CANDIDATE_COMMIT]，行为以该 Issue 固定 Spec 为准。

先核对候选身份、工作树是否被继续修改、批准 Spec 与仓库 Standards。通过后使用独立可销毁测试环境运行验收，不接触生产数据库或客户现场。业务源码只读，允许在既有证据位置写脱敏验收回执和测试产物，不修改候选以使其通过。

不要直接采信实现会话的“已完成”。逐项验证用户路径、错误路径、权限路径与相关历史回归，明确区分真实接口、合成接口和未运行项。

涉及云图阶段时尤其检查：无内部台账/NetFlow也能运行；完整覆盖矩阵；资产和风险详情及依据本地可读；断开云图仍能读已同步内容；分页失败不清空；重复同步不重复；未知字段不伪造；源风险与本地进度不混用。
涉及后续阶段时按其 Spec 检查问题闭环、NetFlow候选语义、Laya启用资格和cumora真实业务调用。

给出每条 AC 的 PASS/FAIL/BLOCKED/NOT_RUN、证据、实际用户影响，以及是否存在交付 blocker。未跑真实来源验证不能称真实集成通过。

发现问题只形成明确缺陷回执，交回原实现任务修复，不顺手改产品或降低门槛。完成后停止，不提交候选、不建新功能、不合并或部署。
```

## P4：候选验收通过后的远端交付

```text
批准正式 Issue #[ISSUE_NUMBER] 的已验收候选 [CANDIDATE_COMMIT] 进入远端交付。

授权本轮执行：push 当前候选、创建/更新对应 PR、运行并核对必需 CI/Review，在满足仓库规则且候选未发生未验收变更的前提下合并；根据真实结果更新本 Issue。
禁止强推、绕过门禁、顺手开发下一项或部署现场。若 CI 发现本 Issue 内缺陷，可以在本范围修复和复测；修复后重新绑定候选与必要验收，不沿用旧候选的通过结论。

PR 绑定批准 Spec、代码版本、独立审阅及业务验收的脱敏证据。核对远端实际状态，不把提交成功、PR 创建成功或 CI 启动当成合并完成。

若本 Issue 要求部署验收，未部署前不得关闭；若部署明确不适用，满足全部验收和合并条件后可关闭。保留历史记录，不因新路线关闭不属于本次授权的旧 Issue。

完成后更新仓库当前入口/交接回执，返回远端结果与下一项唯一建议动作。不自动开始下一 Issue。
```

## P5：单独授权的部署与恢复验证

```text
授权将已合并、已验收版本 [CANDIDATE_COMMIT] 部署到明确环境 [AUTHORIZED_ENVIRONMENT]，范围仅为 Issue #[ISSUE_NUMBER] 要求的组件。

先依据现有部署/恢复文档核对目标、运行版本、活动任务、模型配置、数据库迁移、备份与回退条件。不打印凭据，不把真实数据上传 Git/模型。目标环境、权限或备份恢复条件无法确认时停止该部署，不自行选择生产环境。

按批准方案完成备份、必要恢复验证、兼容迁移、应用切换和本阶段业务验收；保护未涉及的服务与配置。不要自动重新申请模型资格、重跑扫描、纳管或修改外部系统。

失败时按已确认方案回退应用或恢复数据；遇到不可安全逆转的数据迁移，明确停止并保留现场，不盲目 downgrade。

逐项返回部署前后版本、实际验收、数据保护、异常与恢复结果。仅在 Issue 要求均满足时更新/关闭该 Issue。不能用本地测试或镜像构建成功代替部署成功。
```

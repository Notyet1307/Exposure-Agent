## 不变的产品边界

- 云图约定的完整资产、风险、关联及依据同步到 Exposure 本地；断开上游后仍能阅读已同步范围。只同步 IP/数量、外链必经、iframe 或实时透传均不满足。
- 完整范围由实际版本、授权空间、正式接口/导出与字段矩阵界定；未知不猜、缺失不静默删项。
- 新云图同步和阅读不依赖 CustomerUpload、NetFlow、Resource 或旧 GovernanceRun。内部平台保持内部资产主责，Exposure 只读核查上下文；不继续扩建客户台账 CRUD。
- 源风险和本地暴露问题分离；上游判断不被本地进度覆盖。NetFlow 是线索，不能自动成为正式外部资产；Laya 资格验证不阻塞规则版。
- 普通导航按工作台、外部资产（含风险）、核查与处置、报告组织；三账与独立血缘退出普通主导航。历史深链、依据、权限及完整性校验保留。技术 Hash/ID 收入受控详情。
- PostgreSQL、OctoBus、agent-compose 的责任不变；不增加第二调度器、资产主数据平台或默认多 Agent 路径。cumora 调用同一服务和权限，不复制资产/问题权威状态。

## EXP-FOCUS-00：产品收敛接管

- **业务目标**：用代码、实际 Issue/PR 和既有合同确认现状，让下一会话不依赖聊天历史，避免重复开发已交付能力。
- **范围**：只读核对本机/远端/工具；能力四分清单；旧新条款冲突及历史兼容；接口材料盘点和覆盖矩阵；六阶段定义；01A 候选 Spec/Issue；正式入口调整建议。
- **非目标**：业务源码、迁移、生成代码、现场数据、正式建单/改单、commit/push/PR/merge、真实云图/业务模型、扫描/纳管/写回、部署或工具升级。
- **依赖**：本轮用户授权和本地交接手册；已批准旧 Spec/相关已接受 ADR；实际代码/测试与 GitHub 只读权限。接口资料不足只阻塞相关后续工作。
- **完成标准**：接管回执、差异/冲突清单、完整类别覆盖矩阵、阶段落点、01A 正文落盘；明确历史已实现、未知和 BLOCKED；原工作树不被覆盖；草稿未替换批准入口。
- **停止条件**：上述文档及只读验证完成即停。没有真实来源资料不得声称合同或完整同步已验证，不自动进入 01A。

## EXP-FOCUS-01：云图资产与风险本地工作台

- **业务目标**：新项目不提供内部台账/NetFlow、不创建旧 Run，仍可同步、搜索、分页阅读资产/风险详情、关联及依据；上游断连后已有内容仍可读并明确时间/更新状态。
- **范围**：OctoBus 只读合同最小扩展；来源隔离与本地来源读模型；资产、服务、风险、依据覆盖；手动及按批准策略的持续更新；权限、幂等、失败保留、历史兼容；主导航收敛。
- **非目标**：复制云图扫描引擎/后台管理、内部 CMDB、扫描/纳管/外部写入、重写旧 Run/报告、多租户平台重建。
- **依赖**：00 材料；新 Spec 与必要 ADR 批准并固定；对应接口/来源只读权限明确。01A 合同核验先于依赖它的 01B/01C；旧 #238/#240/#242 OPEN 不等于代码阻塞。
- **完成标准**：覆盖矩阵所有约定必需项具备证据；真实合同多页数量/范围可对账；离线可读详情/约定附件；重复不新增；中途失败不清空；风险先到保留待关联；各域时间单独显示；消失不自动修复/关闭；撤权一致生效；旧历史不变；三账/独立血缘退出普通导航。合成测试与真实集成分别记录。
- **停止条件**：每个正式切片交付后停于独立验收/对应发布授权；必需字段或权限缺口未解决则不能把阶段标为完整；不自动进入 02。

## EXP-FOCUS-02：一条暴露问题的核查与处置闭环

- **业务目标**：从一项本地资产/服务/风险，完成提出问题、核查、人工确认、责任/交办、反馈、复测及有依据关闭。
- **范围**：复用核查/追问、人工记录、版本报告；新的来源上下文固定合同；源风险与本地问题分层；最小责任/待办/外部工单引用；问题/任务业务时间线；AI 不可用可手工继续。首次场景选择现有工具实际能验证的问题。
- **非目标**：通用工单平台、自治封禁/关停、任意 Agent 编排、改写旧 Finding 自动关闭规则；缺执行器时伪称已自动处置。
- **依赖**：01 中可靠本地资产/风险消费者；明确问题类型、有效证据和关闭条件；新旧 Run 核查语义隔离的批准规格。外部扫描/写动作另需精确授权。
- **完成标准**：普通用户无需理解 Run/Artifact/Hash 完成一条闭环；源等级/状态不改；已交办、反馈已处理、复测通过分开；复测失败/证据不足/过期数据不能支持关闭；模型失败可保留人工结论和待办。
- **停止条件**：当前切片验收后停止；必须改旧状态语义时先补规格，不静默重解释历史；没有扫描/写授权仅形成计划和人工回执。

## EXP-FOCUS-03：NetFlow 暴露线索与 Laya 资格验证

- **业务目标**：从受控 NetFlow 输入提出有限、可解释、可核查的外部服务线索，不再建设独立资产账。
- **范围**：复用 Dataset 接受、范围/视角、端点投影、候选身份/修订与计数；先规则过滤/聚合/服务线索，再离线比较规则与规则＋Laya；明确有活动、疑似服务、已验证暴露。保留未知归属与客户端通信。
- **非目标**：NDR/SIEM、全流量平台、默认训练、自动建正式外部资产或云图纳管、不经评测默认启用 Laya。
- **依赖**：01/02 的来源/核查消费者；明确网络范围、时间/采样上下文。模型部分另外依赖实际 Laya 仓库/版本/许可证/本地部署资料，不按同名猜测。
- **完成标准**：受管范围外 peer 不进入候选；规则有可解释结果与漏检/误报/不确定评测；新线索可发起核查；Laya 收益、错误分布、资源与置信度有实测才可默认启用；规则/人工不因模型失败失效；旧流记录数、空/absent/UNKNOWN 和报告不改义。
- **停止条件**：规则片完成后可单独交付；模型资料/许可/效果不足仅阻止模型资格或启用，不阻塞规则版；不自动扩展真实目标或训练项目。

## EXP-FOCUS-04：cumora 调用 Exposure 专业能力

- **业务目标**：Web 与 cumora 查询同一资产/风险/问题，提交和读取同一核查任务，不重复维护状态。
- **范围**：先少量只读查询，再核查提交/状态/成果；从 cumora 已有 WeKnora/A2A/MCP 接入路径选最小适配，不并建两套执行链。长期任务返回固定身份和明确状态，权限从服务凭据及主体映射。
- **非目标**：共享可写数据库、另一套资产/问题主表、任意 SQL/URL 工具、绕过 loopback/信任限制、把采用报告当执行许可。
- **依赖**：01/02 固定业务合同；cumora 当时的实际版本、精确信任配置和运行网络；两个仓库各自 Issue/Spec/候选/授权。只读合同研究可以提前，实施仍按单任务；不依赖 Laya 默认启用。
- **完成标准**：从 cumora 真正完成权限内业务查询和一次核查任务，指向 Exposure 同一事项；验证越权、禁用、重放/幂等、未知结果、撤销与成果访问；跨容器/异机真实链路可用，保存连接/metadata 200 不能代替。
- **停止条件**：未批准网络拓扑不扩大任意地址白名单；远端未知不盲重试；一个仓库授权不能扩展另一仓库；不自动授予扫描/写回。

## EXP-FOCUS-05：一体化验收与交付

- **业务目标**：在固定代码/Spec 与授权隔离环境证明整条用户链可用，区分代码交付和部署完成。
- **范围**：云图本地完整阅读→问题→核查/交办→复测→时间线/报告→cumora 查询/任务；NetFlow规则及Laya实际启用状态；主导航/历史、撤权、同步失败、重启恢复、新鲜度和缺口；回退及数据迁移兼容。
- **非目标**：验收时加新功能、降低 AC、造新数据掩盖失败、未经授权部署、把固定响应模型当真实语义验收。
- **依赖**：01—04 所需切片固定候选与批准 Spec；Laya 可明确未启用但规则必须满足合同；部署如果在范围内需独立目标、备份和回退授权。
- **完成标准**：交接手册 A01—A22 的适用项逐条 PASS/FAIL/BLOCKED/NOT_RUN，并给脱敏证据；Standards/Spec 审阅与业务验收分开；真实/合成分开；部署单独记账；旧程序不可误解释新迁移；客户原始数据不进公共证据。
- **停止条件**：任何交付阻断项存在就不宣称整体完成；交付已完成范围、未完成范围及唯一下一动作；不自动部署或进入新功能。
